### Fixed

- A planned long-form that fails (no segments, concat returns nothing, or the montage prepend fails) now stops the day with an error naming the day, the LF and the cause, before any short is rendered. It used to log "skipping" and carry on, so a day spent about an hour on shorts and then died in Phase D with `shorts_per_lf SPLIT-BRAIN`. A resume re-runs a day that was recorded complete with fewer long-forms than planned, even when Phase B/C was checkpointed (the orchestrator now drops the checkpoint when a planned long-form index has no non-empty final, or when `drive_plan.json` is present but unloadable, so phase_bc rebuilds it), so the Galley Head job heals on retry instead of failing Phase D every time. The "Phase BC incomplete" error now names each failed day and its cause. A full_drive day with no supplied plan now builds a montage instead of dropping its long-form.
- The montage prepend concat no longer has a fixed 30-minute limit: it runs under the progress-based ffmpeg runner, so a 38 GB `-c copy +faststart` concat that keeps writing is not killed, and a stalled one still is (partial output removed). A repeated identical ffmpeg stats line (frozen time and size) now counts as a stall, not progress; the concat passes `-nostdin` and no ceiling of its own (the runner's 24 h default stands). The silent `+faststart` moov rewrite is timed by ffmpeg's own progress: growth of its `/proc/<pid>/io` `rchar + wchar` resets the stall clock, and a rewrite whose counters stop is killed after 30 minutes; where the counters cannot be read the window is the larger of the size window and twice the run's elapsed time. The old fixed 20 MB/s floor killed a healthy rewrite of Galley LF1 (38.8 GB) on any volume under 20 MB/s, on every retry. ffmpeg 7 writing to a file prints `frame=    0 ... size=       0KiB time=N/A` before the first packet, judged by `size=`; the `frame=` fallback serves pipe and other non-seekable outputs (`size=N/A time=N/A`).
- A montage clip whose start has no usable keyframe is cut with an accurate seek instead of `-c copy`, which replayed up to one GOP and pushed a 15.0 s montage to 16.7 s. The 10% duration check is unchanged.
- A plan with no `plan_code_version` stamp (written before the stamp existed) now re-enters phase_bc and phase_d on resume, like any plan from other code: it cannot be shown to match the current planner or to confirm every planned long-form. The rebuild costs no encode and stamps the plan. A `drive_plan.json` that cannot be written now stops phase_bc before any encode with the cause, instead of a warning followed by re-dropping the phases on every resume. A day with no score bounds now records its cause in the "Phase BC incomplete" error.
- A healthy `+faststart` rewrite no longer ends with a false "I/O counters became unreadable" WARNING: an exited ffmpeg's unreadable counters are an exit, not a fallback, so the run logs one WARNING naming the mode. A child that keeps reading or writing during the rewrite is bounded only by `max_timeout`.
