### Mask-video materialization — `redactcam.mask`

After writing the sidecar, `BlurDetectionStage._ensure_mask` rasterizes the timeline into a lossless gray **mask video** `_stages/<project>_blur_mask.mkv` and exposes it on `ctx.blur_mask_path` for the composite stage. `active_boxes_at(timeline, frame_idx)` is an O(1) lookup into the per-frame `frame_boxes` map (empty for a frame with no tracked object — so materialization is O(frames), not the O(n²) a per-frame interval scan would have cost); `render_mask_frame` draws white (255) filled boxes on black (0) and Gaussian-feathers the edges (default 8 px) so the alpha composite blends the blur boundary instead of hard-cutting it. Frames are streamed as `rawvideo`/`gray` into one `ffmpeg … -c:v ffv1 -pix_fmt gray` encode at the source's exact `frame_width × frame_height` / `source_fps`.

- **Frame-count hard gate.** `materialize_mask_video` renders exactly `source_frame_count` frames and then re-probes the output with `ffprobe -count_frames`; a count mismatch raises (a mask off by even one frame would blur the wrong pixels). Zero/negative geometry or length raises up front.
- **Resume reuse.** The mask re-renders on a fresh detection; on the resume path (input hash matched) an existing `*_blur_mask.mkv` is reused as-is. Materialization runs before the `PreRenderReview` gate, so the mask is previewable and ready for the stage-9 encode.
