## GPS-speed corroboration of optical stops (`gomoveshift/pipeline/stop_processor.py`)

- **Cross-checks every optical stop against the LF's GPS trace**. Optical stop detection is brightness/motion-based, so a dark tunnel or an under-a-bridge pass can read as motionless while the vehicle is still moving — a false stop the cut would splice out. When `stop_detection.gps_speed_corroboration.enabled` is true AND the LF carries a GPS trace, `StopProcessor` maps each optical stop's source-time span to GPS time with the same linear offset the scorers use (`video_time + effective_offset(...)`), derives per-step speeds from consecutive trackpoints via the shared `_haversine_m`, and takes the **median** (one glitch fix can't swing the verdict). A stop whose GPS speed clears `1.5 × stop_speed_kmh` is dropped as a false dark/tunnel stop.
- **`stop_speed_kmh` knob** (`config.yaml` → `stop_detection.gps_speed_corroboration`): GPS speed above this means "still moving." Default `10.0`. The drop band is `1.5×` the knob so a stop whose pace barely brushes the threshold from GPS jitter is kept, not cut.
- **No-regression guard.** On by default in code; the sample `config.yaml` at the tree root sets `enabled: false`, which keeps the optical-only path byte-identical. The corroboration is a strict no-op when the trace is absent (GPS-less LF), when `enabled` is false, when the trace has no trackpoints, or when speed can't be derived for a span (< 2 timestamped points / no positive `dt`, e.g. a degraded/partial trace) — in every such case the optical stop is left exactly as detected. A span where GPS speed is ~0 (a real stop) is preserved and logged. The stop-removal stage parses the GPX once; a parse failure logs and falls back to `gps_data=None` (optical-only).
