## Canonical ResolvedLocation (one source of truth per LF)

`ResolvedLocation` (`gomoveshift/models.py`) is computed ONCE per LF on the quality-filtered, null-island/teleport-stripped trace and persisted to `state["per_lf_resolved_location"]` so resume reloads instead of re-deriving. Every location surface (title/OST, chapters, description regions, units/playlist/tags) consumes it instead of re-deriving independently — the structural fix for the far-road bleed.

- Fields: `dominant_county`/`dominant_state`, `country_code`/`is_us` (a trailing US state ⇒ miles/feet + US playlist), `ordered_place_sequence`, `regions` (sampled-county union), `vote` (per-county shares), `road` (sampled inside the winning county), `start_label`/`end_label`, `endpoints`, `trace_verified_places` (label endpoint towns proven by the trace — below). Plain JSON-native dataclass so it round-trips state with `asdict`/`cls(**value)`.
- **`country_code` carries the GEOCODED country for non-US drives** (`"US"` for US, the reverse-geocoder's `country` string — e.g. `"Ireland"` — otherwise; `None` only when the geocoder returned no country). Carried INDEPENDENT of state: the country is set whenever one resolves, never gated behind a present state — a STATELESS county (an Irish county with no province-as-state, a US independent city) still has a known country, so it is no longer dropped for want of a state. This is the single signal `region_resolver.derive_region` routes the playlist / units / `social_generator._region_tags` off — a non-US drive's real production label ends in the county/province (`"…, Kerry"`), never the country, so without the carried country the label parse returns `"kerry"` and every Ireland LF wrongly lands in the fallback playlist (`Unsorted (fallback)`, formerly `All Drives`). `is_us` is set from the trailing state alone, so a degraded/absent geocoder (no country) still never flips non-US → US.
- Built by `gps_enrichment.build_resolved_location`. `effective_offset(gps_data, stored_offset)` (`gomoveshift/analysis/shorts_models.py`) corrects a leading null-island or stale-nonzero lock at parse time for all consumers. Empty trace / no geocoder → empty `ResolvedLocation` (callers keep their fallback).
- **Quorum degrade gates on geocoded-sample COUNT, not vote mass — and withholds ALL geocode-derived evidence.** When fewer than `GEOCODE_QUORUM_MIN=2` samples actually reverse-geocoded to a `(county,state)` — read off `DominantLocation.geocoded_sample_count`, NOT the footage-span-weighted `votes` total (a single flaky geocode on a long trace carries a mass above the floor) — the builder returns an evidence-free model: `road`, `ordered_place_sequence`, `regions`, `vote` all empty along with `dominant_*`; only the trace-derived `endpoints` remain. The degraded model is never persisted (the populate storage condition requires a dominant county or regions), so the title fallback and the `location_invariant` gate see no model and skip — the earlier "regions/vote kept" contract instead fed the 1-sample flake to consumers as truth (a correct quorum-derived title could hard-fail post-encode against the single-flake region set). On resume, a legacy persisted earlier degraded entry (dominant-less) is dropped and re-derived.
- Populated by `phase_bc_day_first._populate_resolved_locations`. **Versioned like the color-analysis cache:** each stored model is stamped with `ost_signature` — the fresh `per_lf_ost_text`/title it was derived against. `per_lf_ost_text` is recomputed on every run, so a rehydrated entry is reused only when its signature matches this run's fresh OST text (fast path); on a mismatch (changed trace/geocoder) or an unversioned `None` signature it is dropped and re-derived, so the shipped title and the model feeding units/playlist/tags + the content gates can never diverge across a resume. A resume with no fresh OST text for an LF (defensive/GPS-less path) has nothing to compare and preserves the entry.
- **Label endpoint towns verified against the GPS trace — rescue-only** (`trace_verified_places`, `content_gates.trace_verified_endpoint_towns`). Irish reverse geocodes return the municipal district (`"West Cork"`) as the settlement, so `ordered_place_sequence` can name no village at all and the location invariant refused a correct `"Ballyford to Kilmore, County Cork"` label (wrong-town-in-right-county). An endpoint may carry its own state abbreviation — the cross-state form `"Exampleton, TN to Sampleville, VA via I-81"` — which is not part of the name; the endpoint parser once refused it, so such a label skipped this check and hard-failed on the whole-label fallback. At populate time each `"A to B"` endpoint of the LF's label that the reverse-geocoded truth (place sequence, destination, regions) does NOT already name is forward-geocoded as `"<town>, <region>"` — dominant region first, then each sampled region, stopping at the first that verifies — through `nominatim_source._nominatim_places` (place-class hits only, `limit=5`: the top hit for a village name can be an electoral-division boundary kilometres away). The endpoint verifies when a candidate of exactly its name (case-, accent- and whitespace-insensitive) lies within `_TRACE_VERIFIED_PLACE_KM` (2 km) of an in-window fix; the nearest candidate wins. Verified names join the invariant's town truth only when reverse-geocoded town truth already exists — they never open the check and never make it stricter. Fails closed: no timed trace, no hits, a raising or malformed geocoder → unverified, and the gate fails exactly as before, its message adding that no settlement of that name lies within 2 km of the trace (`TRACE-VERIFIED-PLACE` / `TRACE-UNVERIFIED-PLACE` log each verdict). `None` = not computed (a model persisted before the field; the fast path fills it), `[]` = computed, nothing verified. Stored on the model and covered by its `ost_signature`, so a changed label re-verifies. One builder, `content_gates.resolved_location_gate_dict`, feeds both the pre-encode gate and Phase D's `metadata_json["resolved_location"]`. **Mixed-version resume:** code older than the field raises `TypeError` loading a state file that carries it (`cls(**value)`), so an audit run and its publish run must use the same code.
- **Resume centroid fallback votes**: when an LF has no in-memory trace, the fallback votes the modal county across individual segment centroids (`title_builder.dominant_location`), NOT the bare arithmetic mean (which lands on the wrong side of a county line).
