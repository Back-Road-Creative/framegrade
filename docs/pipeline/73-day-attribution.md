## Day attribution (grouping episodes into calendar days)

`day_grouper._episode_date_key` derives an episode's day key from its **GPX first fix**, shifted to longitude-local time (`gpx_utc + round(lon/15) h`) — the same satellite-UTC clock the county vote / chapters / title already key off. Only when no GPX is reachable does it fall back to the container `creation_time` (naive camera wall clock) and then the `.date` string. The naive path is unreliable because sources disagree on what `creation_time` means: GoPro writes **local** wall-clock, generic-mode Insta360/DJI/phone sources write **true UTC** — so a US-East evening drive after ~19:00–20:00 local would group into calendar day N+1 under the naive UTC key (mixed-day LF, two-area county vote, wrong journal/social date). When the GPX-local date and the creation_time date disagree, it logs a `CLOCK-DISAGREEMENT:` WARN and uses the GPX-local date. First-fix parse is lazy (`gpxpy`) and degrade-not-fail — a missing/garbage GPX drops to the creation_time fallback, never crashes the grouper.
