## Pipeline stages & preflight (implementation)

- **Video Processing**: primary owner. Trigger `gomoveshift pipeline <video>`. 19 stages with interactive review gates (A, Preview, B, Pre-Render, C/D) + 9 automated checks. State checkpointed to `_stages/pipeline_state.json` (stage names, not indices) for resume.
- **Stage/phase graph** (`pipeline-graph.md`): generated mermaid view of `STAGE_ORDER` (grouped by sub-pipeline) + the drive `PHASE_SPECS` order/prereqs. Regenerate with `python -m gomoveshift.pipeline.graph_doc`; `tests/test_pipeline_graph_doc.py` pins committed == generated so it can't drift.
- **tmux persistence gate** (`cli/tmux.process_is_supervised` + `require_supervision`, called from the `drive`, `pipeline` and `batch` handlers): outside tmux, the handlers already enforced persistence in two of three branches — hard error when tmux is absent, detached re-exec (with `--force` appended, since a detached pane is a tty where the preflight prompt would block invisibly) when it is present. The `--no-tmux` branch printed a warning and continued, which let a drive encode launched by another process die with its parent after the raw concat and before any master, unnoticed. The flag now asserts supervision and the assertion is checked: a session leader (`setsid`/daemonised, so no parent shell owns it) or a non-empty `GMS_SUPERVISED` passes; anything else exits 2 with a message naming all three remedies. `GMS_SUPERVISED` is what CI, containers and the suite use — `tests/conftest.py::declare_test_harness_supervision` sets it once, since pytest genuinely is the supervisor and CLI tests pass `--no-tmux` precisely to get a foreground process whose exit code they assert on. Tests: `tests/test_no_tmux_requires_supervision.py`.
- **Drive preflight gate** (`preflight_plan.print_plan`, top of orchestrator): enumerates Phase A + per-day + Phase D with RUN/SKIP + reasons + a wall-clock estimate. `--dry-run` → print + exit 0; `--force` → skip prompt (required for tmux/scripted); non-tty → prompt auto-skipped; tty + no `--force` + non-`y` → graceful abort.
- **Day-master disk check** (`encode_day_master`, before the concat): requires what is still to be written on the stage volume. That is the raw concat's missing bytes (the episode total minus any `day_{date}_raw.mp4` already on disk, which is reused or freed when the concat rewrites it) plus a master of `MASTER_BYTES_PER_SOURCE_BYTE` (1.0) × the episode bytes. Recorded masters measure 0.63–0.89× their source. The old rule was 1.5×, which assumed a 0.5× master and counted an on-disk raw twice, so a day on a tight volume could not resume after a crash, and on a looser volume a master could overrun it. The run-level preflight (`estimate_peak_cache_gb`) still sizes a fresh run at 1.5×, which is now looser than this gate. This gate still fires before the concat, the blur and the encode. Test: `tests/test_day_master_encoder.py::TestEncodeDayMasterResumeSkip::test_disk_space_check_sizes_what_is_still_to_write`.
