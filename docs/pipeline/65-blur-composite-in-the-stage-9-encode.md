### Blur composite in the stage-9 encode — `pipeline/single_pass.py`

When `ctx.blur_mask_path` is set, `process` builds `_build_blur_filter_complex` instead of the bare `-vf`, and `_run_encode_step` emits it with the mask as a **second input** (`-i <mask>`). The graph is `[0:v]<color,scale,fade>[base]; split → boxblur(b2); [1:v]format=gray(mask) → alphamerge(blurred,mask) → overlay(base,blurred+alpha) → <drawtext overlays> [vout]`, mapped with `-map [vout] -map 0:a`.

- **`alphamerge` + `overlay`, NOT `maskedmerge`.** `maskedmerge` requires all three inputs in one pixel format, so ffmpeg promotes the gray mask to `yuv420p` with the chroma planes pinned at neutral 128 → a 50% chroma blend across the *whole* frame regardless of the mask (PSNR-verified: an all-black mask still corrupts the base ~16 dB). Driving the gray mask as the blurred stream's **alpha** and `overlay`-compositing it onto the sharp base reproduces the base bit-for-bit outside the mask and a full blur inside (∞ PSNR), with feathered edges blending proportionally.
- **Blur lands after color/scale/fade, before the text overlays** so the burned OST/CTA pixels stay sharp. The overlay drawtext fragments are byte-identical to the no-blur `-vf` path (regression-pinned). `_build_blur_filter` sizes the `boxblur` radius from `config.drive.blur_strength` (1080p reference, power 2 ≈ Gaussian) scaled by width — stronger on 4K masters.
- **NVDEC prefix injection.** When NVDEC fed the input, the `hwdownload,format=<nv12|p010le>` prefix is injected into `[0:v]` of the filter_complex (same bit-depth logic as the `-vf` path). No mask → the bare `-vf` path is byte-for-byte unchanged.
- **Pinned pixel formats — the base pin is the load-bearing one**. `alphamerge` is 8-bit-only in this build's default negotiation, and **ffmpeg negotiates formats backwards**: that requirement propagated up through `overlay`, through `split`, and into the base chain's `scale`, which then emitted `yuva420p`. So the untouched 10-bit base was flattened to 8 bits *before the blur ever ran* — the whole frame, not just masked regions, on every day master (blur is default-on) immediately before a 10-bit encode. `BLUR_BASE_FORMAT` (`yuv420p10le`) is appended to the base chain **before the split**, which stops the propagation; `BLUR_ALPHA_FORMAT` (`yuva420p10le`) and `BLUR_OVERLAY_FORMAT` (`yuv420p10`) keep the composite itself 10-bit. Measured on the real graph with an all-black (contractually no-op) mask, PSNR outside the mask goes **54.2 dB → inf**. The blur branch still crosses alphamerge's 8-bit surface — unavoidable with this build, and immaterial, since those pixels are boxblurred anyway.
- **The composite gate runs real ffmpeg, not a string match.** `tests/test_blur_composite_depth.py` replaces the `"alphamerge" in fc` check that let this regression ship despite the written-down PSNR discipline: an all-black mask must measure **inf** outside the mask, a half-frame box mask must measure a blurred inside (<40 dB) and an untouched outside (inf), and the base chain's `scale` must not negotiate below 10-bit. Three details are load-bearing and easy to get wrong: the PSNR reference must be an **independent decode** of the source (deriving it from the same `split` makes both sides degrade together and reads `inf` either way, hiding the bug); each `psnr` needs **its own ffmpeg run** (two sinks in one graph leaves one unmapped and its numbers never appear); and every `psnr` must carry **`shortest=1`** plus a per-frame `stats_file=` read. The chain tail converts to 29.97 CFR, so `[vout]` no longer shares a frame timeline with a raw decode. `psnr` pairs its lanes through framesync, which by default repeats the shorter lane's last frame against every remaining frame of the longer one and scores those invented pairs — with the 5 fps fixture that is 24 frames at `inf` plus one fabricated pair at 21 dB, which the aggregate reports as 35 dB and reads exactly like whole-frame damage. `shortest=1` compares only frames both lanes actually produced; the per-frame read is stricter than the old aggregate (one damaged frame can no longer hide in an average) and distinguishes the two signatures directly — real damage is uniform across every frame, a pairing artifact is one or two frames at the tail. Chasing the aggregate instead sends you the wrong way: adding the same `fps` to the reference lane makes it *worse* (28 dB), and regenerating the fixture at `OUTPUT_FPS` so the conversion is an identity op still leaves the tail pair (43.7 dB).
