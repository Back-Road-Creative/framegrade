## Road-sign GPS verification (`--sign-verify`, opt-in)

Every location surface descends from ONE chain — GPS trace → geocoder → `ResolvedLocation`. When the trace and the geocoder agree with each other but are both wrong (drift, a mislabel, a degraded reverse-geocode), no existing gate can tell: they all read the same chain. Road signs are physical ground truth and the only independent evidence available. This is the structural gap the feature fills — not a better geocoder, a second opinion.

**Advisory evidence, never a location authority.** Nothing in the sign path writes, mutates, or returns a location. It only reports agree / no-signal / conflict against the `ResolvedLocation` the pipeline already computed, so the "one resolved location per LF, computed once" invariant is untouched. Default OFF (`config.drive.sign_verify`); the strict escalation is a second opt-in.

**Requires the optional `signs` extra — `pip install -e '.[signs]'`.** `easyocr` is not a core dependency: it drags `torch`, whose Linux wheel unconditionally bundles the CUDA stack (cuda-toolkit, cudnn, nccl, cusparselt, nvshmem, triton). Measured, that is a 5.5 GB environment versus 834 MB without it — ~4.5 GB that a run without `--sign-verify` never loads. Every import is lazy (`analysis/ocr.py` imports easyocr inside the `easyocr_reader` property; `analysis/sign_pass.py` never imports it at all), so the package is only needed when the pass actually runs, and the whole suite passes without it installed. Reaching the reader without the extra raises a `ModuleNotFoundError` naming the install command rather than a bare missing-module traceback. Note EasyOCR is constructed with `gpu=False`, so the CUDA payload torch brings is never exercised — the `gpu` extra exists for onnxruntime-gpu in `redactcam`.

- **Two halves joined by `SignHit`** (`analysis/sign_evidence.py`, plain JSON-native dataclasses that round-trip state with `asdict`/`cls(**value)` like `ResolvedLocation`). The expensive OCR pass is per-DAY in Phase A; the cheap comparison is per-LF at dry-run / phase-BC time when LF spans and resolved models exist.
- **Phase A pass** (`analysis/sign_pass.py::collect_sign_hits`, wired as A6 in `phase_a.py`): days grouped by the real `day_grouper.group_episodes_by_day`, per-episode day-master offsets mirroring `gps_enrichment._build_gps_points_by_date` (same cursor, same `effective_offset`, same in-window clamp). Candidate seconds are MOVING only (`gps_quality.window_median_speed_mps` over a bisect-sliced sub-list — the naive whole-trace call is quadratic), sampled EVENLY and hard-capped per day (`config.drive.sign_verify_max_samples_per_day`, default 120 — the cost governor, bounding native-resolution seeks per day no matter how long the drive is). Each survivor gets ONE native-resolution targeted seek; sign ROI comes from `signs.SignDetector` on that same frame (no second decode), then the local EasyOCR entry point on the crop. Runs on raw PRE-blur footage — blur targets faces/plates/occupants, never signs.
- **The pass is keyed independently of the score cache.** A6 sits BEFORE the score-cache resume gate (the cached `drive_scores.npz` branch) and its early return, guarded on `state.sign_hits_by_date is None`, so a resume with a warm multi-hour scoring checkpoint still back-fills evidence and `PHASE_A_CODE_VERSION` never needed bumping. A read-but-empty day persists as `{date: []}`, not omitted — with a truthiness guard an all-empty drive would re-decode on every resume. Setup failures propagate to phase_a's warn-and-continue (so a broken environment retries next resume); per-second failures are swallowed (so one bad seek can't kill a multi-hour run).
- **Bucketing keys on `episode_index` + `t_local`, NOT a day-master offset** — the same `(source_file_index, start_time..end_time)` coordinates LF segments already use, so assigning a hit to an LF is an exact span test rather than a reconstruction. `sign_verify.bucket_hits_by_lf` therefore requires an UNPARTITIONED plan: `_partition_lf_plans_by_date` remaps `source_file_index` from global to day-local IN PLACE, and bucketing a global-space hit against a remapped plan misfiles evidence into the wrong LF — precisely the desync class this feature exists to catch. Both consumers rebuild a fresh plan via `_build_drive_plan_from_state` for this reason.
- **Claims** (`ocr.parse_sign_claims`, extending the existing pattern table in place): county (BARE name — no `County` filler, so it compares directly against `regions`/`vote` members), state, town, route. Route values are produced by calling the real `title_builder` road-ref member normaliser, so they cannot drift from the via-road vote form they are compared against. Routes match case-sensitively (a case-insensitive match reads "…ahead in 2 mi" as route `IN-2`). The existing noise guards do the heavy lifting: the capture stop-words kill "County Road 12", the `county council` suffix phrase kills "Kerry County Council", and a lone postal abbreviation is never a state claim on its own.
- **Conflict rule is deliberately conservative** — the same conservatism as the far-road gate, because over-flagging trains operators to ignore the gate. ONLY a state or county claim, in ZERO sampled `regions`, asserted by at least `config.drive.sign_verify_min_corroborating_hits` DISTINCT hits, can conflict. One noisy hit never contradicts GPS. Town and route claims are corroboration-only and can never conflict. Region/vote keys arrive as `"County, State"` from the persisted model but `"County|State"` from `dominant_location`, so the comparator splits on either — a single-format reader would silently no-signal every dry-run LF.
- **Silence is not agreement.** No claims → `no-signal`, a distinct third status. An OCR pass that read nothing must never be reported as corroboration, and an LF with no resolved model (GPS-less / legacy / quorum-degraded) is a no-op rather than a conflict.
- **Surfaces.** `--label-dry-run` (`lf_listing.print_label_dry_run`) prints the evidence beside the county vote it is evidence about, WARNs on conflict with the greppable `SIGN-VERIFY-CONFLICT` tag, and still exits normally — the whole block is wrapped so advisory evidence can never break the label gate. `--sign-verify-strict` adds a sibling of the pre-encode location invariant in `phase_bc_day_first`, at the same call site with the same `RuntimeError` contract, upstream of any encode or upload. The strict gate passes NO geocoder: a hard gate must not turn a Nominatim outage into a blocked encode.
- **Egress posture.** Frame crops never leave the box — the sign path calls the local EasyOCR entry point directly, so a revived Claude OCR fallback could not route a frame off-box. Forward-geocoding an OCR'd town name is allowlisted and already sanitised, and is used only on the advisory surface.
