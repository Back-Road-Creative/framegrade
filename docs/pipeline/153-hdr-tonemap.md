## HDR source tonemap (`pipeline/single_pass.py`) <a id="hdr-tonemap"></a>

`SinglePassProcessor._resolve_hdr_source` runs ahead of the SDR gate in `process`. A source with a known HDR transfer curve (PQ / HLG only; `bt2020-10`/`-12` are SDR curves) is tonemapped to BT.709 as the FIRST filter of the colour-analysis sampling, the `-vf` chain and the blur `filter_complex` (`tonemap_filter=`), so the grade is measured on, and applied to, the same post-tonemap SDR frames. The chosen chain is then run on a short synthetic sample and the output is probed (`_probe_converted_sample`); the source is refused unless the result really is `bt709`/`bt709`/`tv`, and `_assert_sdr_source` re-checks the probed tags.

BT.2020 / P3 primaries with a known SDR transfer (`bt709`, `smpte170m`, `bt2020-10/12`, ...) are gamut-mapped only (`zscale:gamut`: linear, primaries to bt709, back to bt709, no tonemap, needs only `zscale`); tonemapping them would darken the grade. The colour-analysis cache records the chain it measured and is re-run when it changes; an SDR master removes any stale `.tonemap.json`.

The operator is recorded as `SinglePassResult.tonemap` (`"<filter>:<operator>"`, also in `to_dict`), logged by both callers, and persisted in `<final stem>.tonemap.json` beside the master (the `.tmp` infix of the atomic-rename path is stripped, so the sidecar survives the rename). SDR masters get no sidecar.

The chain is chosen by installed filter NAME (`_ffmpeg_filter_names`, from `ffmpeg -filters`), never by version: `zscale`+`tonemap` (hable) first, then `libplacebo` (bt.2390) only when `_libplacebo_usable()` proves a device exists by running it once. Refused up front, before colour analysis: no usable chain, or wide-gamut primaries with no known HDR transfer (zscale has no path from an unknown transfer). The error names the missing filters and carries a one-line `ffmpeg -i SRC ... OUT.mkv` command to run with an ffmpeg that has them. SDR and untagged (GoPro) sources are untouched, byte-identical.
