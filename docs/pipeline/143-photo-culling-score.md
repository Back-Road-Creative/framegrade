## Photo culling score

- **`gomoveshift/pipeline/photos/cull.py`** measures three read-only signals per developed RGB photo frame: sharpness (variance of the Laplacian of luma on a bounded downscale, `SHARPNESS_MAX_DIM=960`), exposure clipping (fraction of pixels at/below `CLIPPED_BLACK_LEVEL=2` and at/above `CLIPPED_WHITE_LEVEL=250`), and a 64-bit DCT perceptual hash (`PHASH_DCT_SIZE=32` working grid, top-left `PHASH_HASH_SIZE=8`×8 block of DCT coefficients minus the DC term, thresholded against the block's own median). `compute_cull_score` returns a `CullScore` — a plain measurement, never a verdict; nothing in this module deletes, rejects, or reorders a photo.
- **Near-duplicate grouping** (`hamming_distance`, `group_near_duplicates`) compares pHash values pairwise; two photos within `NEAR_DUPLICATE_HAMMING_THRESHOLD=5` bits are flagged as near-duplicates of each other. The threshold sits above the noise floor measured from a ±2 luma jitter (re-encode noise) and below the distance between visually distinct frames.
- **Surfaced on the console asset page** (`console/library.py: build_asset_context` → `_cull_info`), never in the collection table (would cost a decode per row across a 100-row page). Sibling comparison for near-dup grouping is scoped to the SAME journey + day (`_sibling_photo_hashes`) — typically a burst, and cheap enough for one page view; it never scans the whole journey or library. A photo that can't be decoded (corrupt file, placeholder bytes) gets no cull info and the page still renders — the score is best-effort, not a gate.
- **`selector.py` is untouched.** It picks the weekly social-post rotation across the whole back catalog (round-robin + face-privacy filter), not a review surface — there is no clean hook to wire a per-photo cull score into that selection without changing its behavior, which is out of scope for a read-only review signal.
