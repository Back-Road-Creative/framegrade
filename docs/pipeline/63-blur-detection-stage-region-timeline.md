### Blur-detection stage + region timeline — `pipeline/stages/blur_detection.py`, `redactcam.timeline`

`BlurDetectionStage` runs as stage 5 — **after** `StopRemovalStage` (so it detects on the exact stops-cut file the stage-9 encode consumes) and **before** `ChapterGenerationStage` and the `PreRenderReviewStage` gate (so an operator previews the regions before the irreversible encode). It is a no-op skip unless `config.drive.blur_enabled` is on (**default on**; the blur hard gate below guards every enabled run); diagnostic escape `--skip-blur` (registered `NOT_PERSISTED`, mirrored to `config.drive.skip_blur` in the drive handler (`--no-audio` is the audio analogue, registry-mirrored)).

- **Sparse detection + dense flow tracking → per-frame timeline.** `detect_and_track` runs ONE decode pass: it reads every frame, runs the tiled face∪plate detection only on `blur_sample_fps`-cadence sample frames, and feeds each detection to a `TrackManager` that optical-flow-propagates the boxes across *every* frame (Lucas-Kanade translation + RANSAC partial-affine scale, IoU snap-correct at detections, bounded-horizon retirement — all RNG-pinned, ms/frame). So a fast object caught in a single sample is tracked frame-by-frame, not frozen at the detection spot — the static-union defect the old v1 interval model had (it held one sample's box across the whole gap, blurring early then sitting on bare road). Retirement is **class-aware**: a plate retires the instant flow points are lost (a held fast plate would freeze blur on bare road) and after the tight `track_max_horizon_frames`, but a face COASTS through a flow dropout for up to `track_face_coast_frames` (default 20, > the plate horizon), so a small/low-texture pedestrian face blurs continuously instead of blinking off between detections. The coast is **velocity-predictive**: it extrapolates the held box along the track's last *live-flow* heading (`Track.vx/vy`) rather than freezing it in place — a static hold left 2-3 stale ghost boxes on bare road behind a fast crossing face while the live face went uncovered. The heading is refreshed only from a *plausible* flow step (≤ `_COAST_MAX_STEP × the box's own size`, default 1.5×); a larger "flow" is LK latching onto background on a textureless face, so the prior heading is kept rather than coasting the box off-frame, and a face moving slower than that bound holds in place (the original anti-blink behaviour). Association keeps **one face = one track**, and — since the pin moved to redactcam `2e4b036` — also **one detection ↔ one track per frame**: a track another detection already claimed this frame is off the table for the rest, and `_assimilate` runs two passes so tight IoU matches settle before any loose distance match can steal a track whose own detection overlaps it. Without that exclusivity two co-present cars collapsed onto ONE track, which emits ONE box, so whichever car the track was not currently snapped to rode unblurred — alternating frame to frame with detection order, and carrying the stolen track's plate corroboration to the wrong car. On one measured day master, 13 of 552 corroborated vehicle-frames had an exposed cabin. `_associate` matches a detection by IoU first, then — when IoU fails across fast/small motion (consecutive 8 fps detections of a ~30 px face don't overlap) — by a center-distance gate `max(track_assoc_motion_gain × the SMALLER of the detection/track diagonals, track_assoc_min_gate_px) + track speed` (defaults 1.2 / 72); the smaller diagonal is what stops a big near car's track reaching most of a 4K frame across to swallow a small distant car's detection. The size term widens the gate for big near faces; the **flat floor** is what catches a *tiny distant* face — its tight box is ~17 px, so the size term alone (~31 px) falls under the ~45-55 px the face moves between sparse detections, and without the floor each detection spawns a fresh track that freezes into a ghost (measured: two stale 32 px boxes lingered ~0.35 s behind the live face). With the floor the early detections snap one track forward until the face is big enough for flow to establish a heading and the velocity coast takes over. `_retire_superseded` then drops any coasting ghost a freshly-detected track of the same class overlaps. Three further **exit-ghost / duplicate** guards keep a coast from outliving its object: (1) a face whose coast is **moving** (per-frame displacement ≥ `track_coast_move_speed`, not the heading — a coast whose flow latched onto a fast-passing car body has a ~0 heading yet moves hundreds of px/frame) retires after the short `track_face_coast_moving_frames` (6) instead of the full `track_face_coast_frames`, since a coast traversing new area is far more likely ghosting past an object that left frame than a static hold of a present-but-missed face (only the dead tail after the last detection is trimmed — a mid-traverse gap is interpolation's job); (2) a face pinned against a frame edge whose last detection is >1 frame stale is retired (`track_retire_edge_coast_margin`) — the exit-ghost a pedestrian/occupant leaves off-frame, whose held box re-seeds flow points on the static background it parks over (a wall at x=0), so it looks flow-alive yet tracks nothing and a points test misses it (measured: a pedestrian's blur stayed on the wall for ~17 frames, and a car occupant's froze a blob at the lower-right corner for ~9); (3) `_dedup_overlapping` retires the weaker (fewer detections) of two same-class tracks overlapping by more than `track_dedup_iou` (0.55) — a fast/sparse object that spawned a second track the association gate didn't merge — a high threshold so two genuinely distinct crossing faces aren't merged. Each emitted box also carries a **motion margin**: `TrackManager` grows it by `track_motion_gain × the box's own per-frame flow speed`, capped at `track_motion_max_px` (defaults 1.0 / 160) and floored — for plates only — at `track_plate_margin_floor_px` (default 16). LK underestimates large motion, so a fast oncoming plate's flow box trails the real plate between 8 fps detections (it was briefly readable at the frame edge); a speed-scaled margin covers that lag exactly where it's worst, while a near-static box — including a large structure FP — gets ~no speed margin (the margin scales with **speed, not size**, so it never balloons a big slow box, the failure mode a size-scaled margin had). The plate floor is a small *flat* (size-independent, so likewise non-ballooning) minimum that covers a **slow/distant** plate, whose speed margin is ≈0 yet whose tight box can still expose the plate. Faces get the analogue but **size-proportional** — `track_face_margin_frac` (default 0.35, config `blur_face_margin_frac`) × the box's larger side: a face's speed margin *also* collapses to the bare frontal-detector box when its flow speed drops to ≈0 (a pedestrian *exiting* frame loses her flow features), and the frontal box is tighter than the visible head, so her turned cheek/profile pokes out at the soft blur edge on the leading side as she clears frame-left (measured on a pedestrian's close-pass exit over ~9 frames). A proportional floor keeps coverage on the whole head without ballooning a *tiny distant* FP face (its floor scales down with it, unlike a flat constant — precision held); 0 restores the old speed-only behaviour. Faces also take a higher speed-gain than plates — `track_face_motion_gain` (default 1.6, config `blur_face_motion_gain`) vs the shared `track_motion_gain` (1.0): a fast face's flow box lags its true position more than the symmetric speed margin covers, so its blur trails to the right of a fast leftward subject and collapses as it exits frame (a pedestrian's close-up still read through, and a driver re-appeared as the car cleared frame-right); the larger face gain pads the leading edge and the trailing exit, while plates keep the lower gain (over-padding a plate balloons structure FPs). `redactcam.build_timeline` then adds the flat `blur_box_dilation_px` privacy backstop (clamped to frame bounds) and stores the result as a dense `frame_boxes` map; a frame with no tracked object carries no blur. The mask-video stage rasterizes the per-frame boxes into a frame-accurate mask; the composite stage applies it.
- **Adaptive plate cadence** (`blur_plate_boost_speed_px`, default 8; `blur_plate_boost_max_run`, default 6; 0 disables). Flow-tracking alone can't follow a moving oncoming plate between the sparse 8 fps samples: the box lags and the plate pokes out the trailing edge of the mask, readable for the in-between frames. Worst case is the *extreme* close pass — as the source car passes within a metre the plate accelerates ~190 px/frame, far beyond what LK estimates from a 31 px window (the plate can poke well outside the mask between sparse samples and be legible in the composite) — but the exhaustive per-frame audit found the same lag-leak on *moderate*-speed oncoming plates too (each readable for a few non-sample frames). The detection is *reliable* at those frames (the plate is head-on); the gap is purely cadence. So while any plate track's per-frame flow `speed ≥ blur_plate_boost_speed_px`, `detect_and_track` forces a plate-only re-detection on *every* frame (`_next_boost_run` re-arms a countdown to `max_run`, decaying past the last fast reading to bridge a momentary flow dip, then self-clearing when the plate retires and `TrackManager.max_speed("plate")` → 0). The threshold is set low (8 px/frame) so *any* moving plate triggers it, not just an extreme pass; a static/parked plate (speed ≈0) doesn't drift out of its box so needs no boost. The boost ALSO re-arms on a **recently-seen** trigger — any plate *detection* re-arms per-frame re-detection (`_next_boost_run(..., plate_seen=True)`) — because a small distant plate won't hold optical-flow features between samples (it retires with no surviving track for the speed gate to read), so detection itself drives the cadence through the rest of its pass. Each boost frame snaps the box onto the ground-truth plate. The boost re-runs only the plate detector, so cost is bounded to the frames a plate is on screen, not the whole run — plate detection is the stage bottleneck (~2.5 h/LF at the base cadence), so a *global* cadence raise was not viable. The residual is a pass whose *first* sample is missed (a brief pass falling between samples, or a borderline sub-conf score) — covered only at the price of a higher base cadence, deliberately not paid.
- **Anchor interpolation between detections** (`TrackManager.confirmed_frame_boxes(..., interpolate=True)`). Optical flow freezes or drifts a *small* low-texture object (a distant plate, a small face) between sparse detections; a detection at each end of a gap pins the true endpoints, so each track's between-detection gap boxes are replaced by the straight-line interpolation of the bracketing boxes (`_interpolate_gaps`). Frames before the first / after the last detection keep the flow box. This covers the mid-gap drift the boost doesn't (and smooths a walking pedestrian's box between face samples), at zero extra detection cost.
- **Backward pre-roll** (`blur_pre_roll_frames`, default 5; `TrackManager._pre_roll_boxes`). The forward boost + interpolation cover a track from its first detection onward, but a small/distant oncoming plate is *readable* — and a pedestrian *present* — for the few frames it's visible BEFORE the detector first scores it ≥ conf (its head). So a confirmed, moving track's box is extrapolated BACKWARD along the velocity of its first two detections for up to `blur_pre_roll_frames` frames before the first detection. The box shrinks going back (a growing approaching box collapses — and the pre-roll stops — once it would be ≤0, i.e. before the object was there), and only confirmed moving tracks pre-roll, bounding the bare-road-blur risk to a few frames. This is the last bounded-cost lever; the residual beyond it (a plate visible longer than `pre_roll` before any sample catches it) needs a base-cadence raise, deliberately not paid.
- **Vehicle-detector cabin blur** (`blur_vehicle_cabin_frac`, default 0.6, 0 disables; `blur_vehicle_conf`, default 0.6; `vehicle_model_*`; `TrackManager._emit_box`). A vehicle's occupants sit behind a moving windshield where per-face detection is unreliable (the face model fires on the wall/roof/glass reflections, never the face). The FIRST attempt anchored the cabin to the tracked **plate** and extended it up+wide; it FAILED — the plate is at the front of the car but the windshield leans up-and-*back*, so the box went tall into the sky and left the windshield wide open as the car passed (an exposed driver on every side-pass). The fix locates the **whole car**: a COCO vehicle detector (`VEHICLE_CLASSES` = car/bus/truck/motorcycle, no aspect gate) boxes the vehicle — cars are large/high-confidence, so it runs whole-frame (no tiling) on the base cadence and is flow-tracked like any other class. `blur_vehicle_conf` is set HIGH (0.6) to drop the *weak* sign FPs (a wall-mounted board scores ~0.35-0.55 while real cars score 0.63-0.95), but confidence alone is NOT enough — a large roadside object (a billboard on a flatbed trailer, a parked caravan) scores **as high as a real car (0.7+)** when close, so it can't be thresholded out. The decisive separator is **plate-corroboration** (`_corroborate_vehicles`): a vehicle's cabin is blurred only once a tracked license **plate's center falls inside the vehicle box** — a real road car has a plate, a billboard/sign/caravan does not (verified: a billboard-trailer produced zero plate detections across its whole approach while a real car showed a plate on every close frame). It's sticky (the plate isn't re-detected every frame) and self-scoping: a car close enough for identifiable occupants is close enough for its plate to detect. The blur is the **top `blur_vehicle_cabin_frac` of that (corroborated) box** (`_emit_box`), which contains the occupants at EVERY viewing angle — the windshield head-on, the side windows on the pass — so the driver is covered through the whole pass without ever localizing a through-glass face. Two more refinements the verifier forced (it measures every frame, not four): (1) a worth-blurring filter (`redactcam.detect.filter_vehicles`) drops vehicles below `blur_vehicle_min_height_frac` of frame height (a distant car with no identifiable occupant) and any whose box top is in the bottom `blur_vehicle_ignore_bottom_frac` strip (the EGO car's own hood, which COCO fires on as a 'car'); (2) a present worth-blurring vehicle ARMS the per-frame detection boost (alongside the plate boost), because flow drifts a fast-scaling car box onto the road between sparse samples — so the cabin is snapped to a fresh detection every frame of the pass, not flow-tracked. The emitted box is the TIGHT (snapped) box, no speed-margin (it ballooned a drifted box; the fraction already over-covers). The plate blur (lower car) and pedestrian-face blur are unaffected. The vehicle detector is built only when `blur_vehicle_cabin_frac` > 0 and the model resolves; an unresolvable model disables the cabin blur (WARN, never fatal). Coverage is checked, not eyeballed, by `tools/verify_blur_coverage.py` (next bullet).
- **Whole-person blur** (`blur_person_enabled`, default on; `blur_person_conf` 0.35; `blur_person_min_height_frac` 0.05; `person_model_*`; `redactcam.build_person_detector`, `redactcam.detect.PERSON_CLASSES` = COCO class 0). The face + cabin path covers a person's HEAD but not their body/pose — an operator standing OUTSIDE the vehicle (a parked operator once shipped in a short) got at most a face blur. So a COCO person detector (the SAME yolo11n model the vehicle detector uses, class-filtered to person 0) boxes the WHOLE person on the base cadence, and the mask blurs the full box: `person` is a generic non-face/non-vehicle class in `TrackManager`, so it emits the whole motion-padded box (no cabin fraction) and is always emitted (no plate-corroboration requirement — unlike the vehicle cabin). Height-gated by `filter_vehicles(min_height_frac, ignore_bottom=0)` to drop tiny distant dots; an unresolvable model degrades to WARN (faces still ship blurred), never fatal. Wired into BOTH the single-video `BlurDetectionStage` and the drive `_build_day_blur_mask` via the same `config.drive.blur_person_*` knobs, so the two paths never drift.
- **Cabin-coverage gate** (`redactcam.verify_cabin_coverage`, shared core `blur_gate._cabin_coverage_error`; wired as `blur_gate.check_cabin_coverage`, called pre-encode in `single_pass_encode` (legacy per-episode path), and as `blur_gate.check_day_master_cabin_coverage`, called pre-encode in `day_master_encoder.encode_day_master` right after the day mask is built (drive path) — same semantics on both, so the two paths never drift; dev CLI `tools/verify_blur_coverage.py`). The objective guard that the plate-cabin failure escaped (it shipped on a four-frame eyeball). Independent of how the blur was made: it re-detects vehicles in the BLUR INPUT (same conf + worth-blurring filter + plate-corroboration as the blur, so it checks exactly the cars the blur is responsible for and never the billboards/caravans it leaves readable) and, for each corroborated car's cabin region (top `cabin_frac` of the box), confirms the **blur MASK** covers ≥ `blur_cabin_gate_min_coverage` of it. A cabin the mask misses is an exposed driver → a `Leak`; any leak hard-fails the run BEFORE the irreversible encode. Checked against the MASK, not the FINAL, because the FINAL also carries the color grade + OST burn (a diff can't isolate the blur) while the mask is exactly what the encode will composite — same answer, no confound, runs earlier. Sampled at `blur_cabin_gate_sample_fps`; reads input + mask in frame-locked lockstep. Paired with the cheap **model-resolve hard-fail** in `BlurDetectionStage` (cabin blur on + vehicle model unresolvable → fail, never silently disable) so the realistic future-regression — a model that won't load — can't ship drivers exposed. Both bypass with `--skip-blur` / `blur_vehicle_cabin_frac=0`. The dev CLI verifies a reval blur-only mp4 by pixel-diff instead (no mask handy). **The full leak list is persisted, not just the 5 worst named in the error** (`blur_gate.cabin_leak_report_path` → `<mask_stem>_cabin_leaks.json`, beside the mask so the two travel together across a resume). The error string can only carry a handful of examples, and a measured failure showed what that costs: 13 leaks reported 5 at a time, and re-deriving the rest meant re-scanning a 353k-frame master for hours even though the gate had already computed every one of them. A passing gate `unlink`s the file, so a green run can never inherit a previous failure's list; a write error only warns (a diagnostics file must never mask the leak itself).
- **Sidecar + resume.** The timeline serializes to `_stages/<project>_blur_regions.json` (schema `redactcam.timeline/v1` — a pre-rewire `blur_regions/v2` sidecar mismatches and safely recomputes) keyed by `compute_file_hash` of the **input** (stops-cut) file; on resume a matching `source_hash` skips re-detection entirely (re-cutting the stops invalidates the hash and forces a redetect; a v1 sidecar mismatches the schema and safely recomputes). `detect_and_track` returns the exact decoded frame count, authoritative for `source_frame_count` (driving the mask-video stage's strict `mask_frame_count == source_frame_count` assertion) over cv2's best-effort `CAP_PROP_FRAME_COUNT`; `frame_width/height/fps` come from the probe. A detector error is **fatal** (`StageResult(success=False)`) when blur is enabled — never proceed to the encode unable to locate faces/plates.
