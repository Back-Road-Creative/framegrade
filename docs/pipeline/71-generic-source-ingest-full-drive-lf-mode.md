## Generic-source ingest + full-drive LF mode

```
gomoveshift drive <source-dir> --ingest-mode generic --lf-mode full_drive \
  --lf-day tue --per-lf-location '1=Exampletown to Samplevil via R100, Kerry'
```

- **`--ingest-mode {gopro,generic}`** (default `gopro`): `generic` = one file per singleton episode/day; recording day from ffprobe `creation_time`, else a `<name>.gpx` sidecar (day_grouper derives the longitude-local day from its first fix). With neither, the scan **hard-fails** naming the file — file `st_mtime` is copy/offload time, never the recording day (stamping it groups a day-N drive offloaded on day M into day M's slot). Mixed-mode raises at scan.
- **`--day-gpx PATH --camera-utc-offset-hours N`** (`pipeline/ingest/day_gpx_slicer.py`): slices a whole-day GPX into one `<stem>.gpx` sidecar beside each `VID_YYYYMMDD_HHMMSS_*.mp4` in the source dir, before ingest. `N` is **required** with `--day-gpx` and never guessed (camera local = UTC + N; US Eastern DST = `-4`). Window per file in UTC = `[start-15s, start+duration+120s]` (the 120 s tail is the endpoint-loss pad, the `A2B-ENDPOINT-LOSS` log token); start comes from the filename time and the offset, duration from ffprobe. A recording split into chapters (same `HHMMSS`, consecutive `NNN`) starts each chapter where the previous one ends: the filename time plus the earlier chapters' durations. A chapter whose predecessor is missing is refused, because its start cannot be known; Phase A's 60 min start tolerance would not catch a 30 min chapter sliced at the recording start. Refused loudly: a file with no trackpoints in its window (wrong offset/day), any `.mp4` whose name is not `VID_YYYYMMDD_HHMMSS_NN_NNN.mp4` (strict filename contract; `LRV_*` proxies are skipped, not refused), a window that fails the existing Phase-A correspondence gate (e.g. a ~5 min clip, where the pads exceed the 120 s span tolerance; the gate is never loosened), and an existing `<stem>.gpx` the slicer did not write (sidecars it wrote carry `creator="gms-day-gpx-slicer"` and are rewritten). All slices are validated before any is written. A >60 s gap between ffprobe `creation_time` and the filename-derived start logs a warning (Phase A gates on `creation_time`). Not run under `--dry-run` (plan only); `--list-lfs` still slices because Phase A reads the sidecars.
- **`--lf-mode {best_moments,full_drive}`** (default `best_moments`): `full_drive` = one LF per maximal contiguous span of the day master with the parked/stopped seconds removed by the **per-day stop mask** (`_full_drive_unmasked_ranges` splits at masked spans; nothing re-cuts the source — the mask is the only thing that excludes stops). `plan_regular_lfs(mode="full_drive")` **requires** a `stop_mask`: `stop_mask=None` raises `ValueError` instead of silently collapsing to a single whole-timeline span with parked seconds included. A mask that keeps every second (all-`False`) is the explicit way to get that single whole-timeline LF. `DEFAULT_MIN_DURATION_SEC=480` floor / `full_drive_max_duration_sec=7200` ceiling both raise (no silent truncation), checked against the KEPT (unmasked) duration. `trim_ratio ≥ 0.5` auto-fires the `"Driving"` verb.
- **Balanced parts** (`full_drive_part_min_sec` / `full_drive_part_max_sec`, both `None` by default = one LF per day; the sample `config.yaml` shipped at the tree root sets 3600/5400 so full-drive days split into 60-90 min long-forms; `DriveConfig` rejects one without the other and any `0 < min <= max` violation): when both are set, `split_ranges_balanced` splits the day's kept ranges into `K = ceil(kept/max)` near-equal parts (`K` drops by one if `kept/K < min`, so a part may run over max but never under min; a 91-119 min day ships as ONE part). Cuts snap to the stop-mask range edge nearest the even-split target inside the feasible window, else cut mid-range (bisected `integrated_score`, a SUM, splits proportionally to duration). The 480 s floor and `full_drive_max_duration_sec` ceiling then apply PER PART (raise, never truncate). `_build_full_drive_plan_per_day` emits one `RegularLFPlan` per part (`global_lf_index` increments, `part_index`/`part_count` set); the legacy non-day-first path raises if the split yields >1 part. A split part that yields no segments raises rather than being skipped. **Render**: `run_day_pipeline`'s full_drive fallback goes through `plan_full_drive_parts` when both fields are set and synthesizes K `RegularLFPlan`s (indices 1..K, unique, so `lf_01.mp4`, `lf_02.mp4`… and every `lf_NN.*` sidecar/work file are distinct); supplied `lf_plans` are accepted iff indices are unique and each part is within `full_drive_max_duration_sec` (with the fields `None` the old exactly-one-plan rule stays). The DoD duration ceiling is per rendered LF file. `gate_a` skeleton indices are `[1]` without parts; with parts they come from the drive plan once phase_bc has planned (else `None` -> drive-wide label).
- **GPS-optional**: `_redistribute_gps_weights` rebalances GPS-dependent weights when no `.gpx` sibling; `route_context`/`stages/chapters` emit empty artefacts. `--per-lf-location` required for every GPS-less LF.
- **`--lf-target-duration MINUTES`**: exactly one highlight LF of a given length. Enables `best_moments_mode`, clamps target min==max, widens `max_lf_duration` (1.2×) / lowers `min_lf_duration` (0.8×, floor 60s). Rejected with `--lf-mode full_drive`; non-positive rejected (exit 2). `best_moments_mode` is internal plumbing — do not set in YAML.
- **best_moments segment filter** (`_dynamic_best_moments_filter`, runs when `best_moments_mode`): default RELATIVE bar — keep top-scoring segments above the `best_moments_percentile` quality floor, padding up to `best_moments_target_min` (min_keep_ratio guard). Opt-in ABSOLUTE bar (`best_moments_absolute_floor_enabled`): keep every segment with `composite_score ≥ best_moments_absolute_floor` (default `0.26`, ~p75 of GPS-less visual-only composites), so coverage scales with footage quality and a sparse drive floors to one solid LF (never padded, never empty — keeps the single best segment if none clear the bar). **Mode-aware**: GPS-present days have a shifted/higher composite distribution (GPS mass live, not redistributed), so the absolute path falls back to the percentile bar (`has_gps` threaded from `gps_per_episode`) until a GPS floor is calibrated.


## LF policy resolution (2026-10-15)

- `lf_selection_mode` defaults to unset. Unset + both `full_drive_part_min_sec`/`full_drive_part_max_sec` -> `full_drive` (a compatibility MIGRATION, logged `LF-POLICY-MIGRATION`); unset otherwise -> `best_moments`. Explicit `best_moments` (yaml or `--lf-mode`) with bounds set is honoured and logged `LF-POLICY-OVERRIDE`; it is never the silent fallback.
- Readers call `config.resolve_lf_mode(drive)`; `lf_mode_source` records default/yaml/cli/resumed-state and the launch banner prints it with the bounds.
- A day whose kept (stop-masked) footage is under `full_drive_part_min_sec` raises `InsufficientFootageError` (planning, before any encode). One LF covers one calendar day: no padding, repeating, slowing or joining days; there is no escape flag.
- Resume: neither `pipeline_state.json` nor the flag registry carries the mode or bounds, so a resumed run uses the current config; the saved plan is compared with `lf_policy.json` (stamped when phase_bc completes) and phase_bc/phase_d re-run on a change.

## full_drive GPS-gap mask (2026-10-21)

A place named in viewer text means every retained second is provably inside it, so `full_drive` planning never retains a span with no GPS fix. `longform_assembler._with_gps_gap_mask` ORs the shorts planner's GPS-gap veto (`stop_mask.build_gps_gap_mask`) into the day's stop mask before `plan_full_drive_parts`, on both the day-first and legacy paths. Threshold is `stop_mask.GPS_MAX_FIX_GAP_S`, which IS `route_claims.GAP_S` (no new constant): a lead before the first fix, a fix-to-fix interval, or a tail after the last fix longer than it is cut out of the LF ranges (balanced parts and the 480 s floor then apply to what is kept). A day with no GPS at all masks nothing extra (operator `--per-lf-location` label); a `None` stop mask is still refused. This is upstream of the route-claim gate, which is unchanged: it was refusing every label on a drive whose first ~718 s had no fix (Ace Basin 2026-02-21). The mask is applied at plan time and phase_bc's code-version fingerprint gates reuse of a plan built without it.
