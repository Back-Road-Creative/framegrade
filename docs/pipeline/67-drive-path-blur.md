### Drive-path blur (day master) — `pipeline/day_master_encoder.py`

The single-video chain above blurs the stage-9 master. The DRIVE (day-first) path has no such stage — regular LFs are stream-cut from a day master, shorts are cut from it, and thumbnails derive from the LF FINAL — so the blur is wired into the **day master's ONE existing single-pass encode** (which already re-encodes the whole day for color + audio). `_build_day_blur_mask` runs the SAME `detect_and_track` → `redactcam.build_timeline` → `blur_mask.materialize_mask_video` flow on the raw concat the encode consumes, and `encode_day_master` threads the mask into `SinglePassProcessor.process(blur_mask_path=…)`. So the day master is blurred **by construction** and every LF/short/thumbnail cut from it inherits the blurred pixels for free — one detection pass, no extra encode. (Blurring each of the day's N LFs + 14 shorts separately would re-detect N+14× AND re-encode every otherwise stream-copied surface — strictly more work and less robust.)

- **Why the day master, not per-surface.** The master is the single source every downstream surface derives from, so blurring it is the robust-by-construction point. Keyed on a cheap `size:mtime` fingerprint of the concat (a full sha of a 100 GB file is prohibitive) so a resume killed AFTER detection but before the encode reuses the mask instead of re-detecting a multi-hour master. When the mask is built on the raw concat itself (no deflicker/stabilize step), the key is the concat's provenance instead (`_concat_provenance_fingerprint`: each episode's `size:mtime_ns` in order plus the raw's size), so a raw rebuilt from unchanged episodes after a failed run keeps its mask; a mask keyed on the raw's own fingerprint by an older run still matches while that raw is untouched. Added after a rebuilt 132 GB Ace Basin raw, the same size to the byte, restarted a finished ~16 h detection. redactcam's mid-pass checkpoint still keys on the raw's own size and mtime, so a rebuild discards a partial pass. A crash DURING detection resumes too: the day master passes redactcam a checkpoint (`day_{date}_blur_regions_detect_checkpoint.json`, a snapshot every `BLUR_CHECKPOINT_EVERY_S` = 300 s of video), and a re-run seeks to the last snapshot minus redactcam's 90-frame overlap and unions the boxes. redactcam checks only the source fingerprint, so a `_detect_checkpoint_binding.json` sidecar records the blur evidence and every detector setting the checkpoint was made under; any difference deletes the checkpoint before detection starts, so stale boxes never enter a pass with a new model or threshold. Both files are removed once the mask is written. On a resumed pass the logged face/plate counts cover only that call's detections. Added after one 132 GB day lost ~8 h of detection to a single CUDA fault at 54%.
- **Hard gate — reuses `blur_gate`.** Blur is required = `blur_enabled ∧ ¬skip_blur`. A blur-required run must never REUSE a cached master that predates blur: a successful encode stamps `day_{date}_master.mp4.blurred` (`blur_gate.mark_applied`), and the resume shortcut calls `blur_gate.require_master_blurred` and raises `BlurGateError` when the marker is absent — upstream of the LF/short cuts, so upstream of any Drive/YouTube upload. A detection failure or an unresolvable cabin model likewise raises `BlurGateError` (never a silent fall-through to an unblurred encode). `run_all_days` RE-RAISES `BlurGateError` (like `OstAuditPendingError`) instead of swallowing it into a per-day skip, so the run aborts loudly rather than shipping the week thinner. Escape: `--skip-blur` (no-ops the whole path) or re-run `--fresh`.
- **`--skip-blur` is functional on drive runs.** The old drive-handler rejection of `--skip-blur` (it used to be a no-op) is removed — the flag now mirrors to `config.drive.skip_blur` and the day-master encode honors it, exactly like the single-video path. `--skip-stop-verify` stays rejected (its only consumer is the single-video stop-removal stage).

> **Privacy purpose.** GMS footage is shot on public roads; the blur anonymizes bystanders' faces, other vehicles' plates, vehicle occupants, and whole persons before anything reaches YouTube/Drive. Audio voice redaction and per-region gating are intentionally out of scope (operator chose blur-everywhere). The detector is best-effort, not a legal guarantee — `--skip-blur` exists for footage already known clear.
