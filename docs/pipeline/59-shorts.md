## Shorts (9:16)

- Encode at exactly **1080×1920 9:16** (`gomoveshift/pipeline/shorts_extractor.py`): single ffmpeg invocation center-crops the day master, scales, composites OST. Phase D enforces dimensions via `ShortsValidator.validate_short_files` before Drive upload (non-1080×1920 raises).
- Shorts skip logo + persistent URL but keep OST title + YouTube CTA + end-card.
- **Crop dimensions are rounded DOWN to even** (`ffmpeg_filters.build_crop_filter`): 4:2:0 subsamples chroma 2x on both axes, so an odd crop dimension is not representable and ffmpeg silently rounds it — the effective crop window stops matching the computed one. Every common source hit this (3840×2160 → `crop_w=1215`, 2704×1520 → 855, 1920×1080 → 607); the round is always down, since a crop larger than the source makes ffmpeg fail outright. The ≤0.05% aspect shift this introduces stays well inside 9:16.
- **Shorts OST gate** (`day_pipeline._gate_short_ost_text`): each short's text runs `shorten_ost_for_shorts` (strip `via …`/`Scenic Drive`, then **region-preserving** truncation to 40) then `validate_ost(text,"shorts")` before the irreversible burn; on rejection falls back to the parent LF's `per_lf_ost_text`, then empty overlay (`SHORTS-OST-GATE` WARN). `write_shorts_ost_audit` writes `shorts_ost_audit_<date>.json`.
- **Per-short place provenance** (`day_pipeline._render_day_shorts`): each `shorts_ost_audit_<date>.json` entry carries `place_source` — `"clip_gps"` when the burned text is this clip's OWN GPS vote (`short_ost_text_fn` over the clip's on-screen trackpoints via `trim_gps_to_clip_timeline`), `"lf_label"` when it degraded to the inherited parent-LF/drive-wide text. Excluded from `compute_shorts_ost_audit_hash` (`_HASH_EXCLUDED_ENTRY_KEYS`) — it annotates which input won, it isn't a burn input itself, and a genuine change in the winning source always changes `ost_text` too.
- **Region-preserving truncation** (`ffmpeg_filters._truncate_region_preserving` for the 40-char shorts budget, `day_pipeline._fit_shorts_title` for the pixel-fit shorts hard-fit, `title_builder._drop_trailing_clauses` for the 100-char LF-title fallback): an over-budget "Town, County X" drops the whole trailing comma clause (", County Kerry", ", SC") first — keeping the distinguishing town — and only word/char-chops as an absolute last resort, so "Exampletown, County Kerry" degrades to "Exampletown", never a dangling "County" or a mid-word "Count". A word-level chop that lands right after an arc joiner also strips the orphaned trailing connector token (`ffmpeg_filters.strip_trailing_connectors`, set `TITLE_CONNECTOR_TOKENS` = the assembly joiners `to`/`via`/`+`): "Exampletown to Samplevil…" degrades to "Exampletown", never "Exampletown to"; `validate_ost` rejects any dangling connector that slips through as the pre-burn backstop.
- **Shorts pre-burn OST review gate** (`day_pipeline._render_day_shorts` → `ost_audit_sidecar.shorts_gate_or_raise`): the per-LF OST audit gate runs before any short exists, so shorts burned text used to reach the irreversible 9:16 burn with no operator review. `_render_day_shorts` now runs in two passes — derive every short's final burned text, then burn — with `shorts_gate_or_raise` between them: it writes `shorts_ost_audit_<date>.json` for review and raises `OstAuditPendingError` unless confirmed via a `shorts_ost_audit_<date>.confirmed` file, `state["shorts_ost_audit_passed"][date]` + matching `shorts_ost_audit_hash` (`compute_shorts_ost_audit_hash`), or `state["ost_audit_confirmed"]` (the shared `--ost-audit-confirmed`, one signal for both surfaces). `confirmation_is_stale` reopens the gate when any short's burned text changed materially since the confirmed run (hash excludes `generated_at`). The post-burn `write_shorts_ost_audit` in `run_day_pipeline` still re-emits the final confirmed copy for the Phase D per-short labels.
- **Shorts post-burn OST pixel proof** (`day_pipeline.run_day_pipeline` → `ost_audit_sidecar.postburn_ost_gate_or_raise` → `ost_text_present_in_pixels`): the pre-burn gate and the `shorts_ost_audit_<date>.json` it writes are an ATTESTATION — they record the text each short was asked to burn and read identically whether drawtext composited it or the filter chain dropped it. The render loop now back-fills `path` onto each rank's audit entry (excluded from `compute_shorts_ost_audit_hash` alongside the other diagnostics — it is where the artefact landed, not what was burned, so an `--output-dir` change can't reopen a reviewed gate), and `run_day_pipeline` opens every rendered short: three frames from inside the title's full-opacity plateau (1.0/2.5/4.0s, before any CTA can share y=280), native width, comparing the min(near-white, near-black) pixel share of the title band at y=280 against a control band at 0.60·h in the SAME frame. Measured margins: ~4% for a four-letter county, ~18% for a wrapped arc, 0.00% for bare footage against a 1% floor and a 3× lift over control. `OstPostBurnError` hard-fails upstream of phase_d's upload — it sits OUTSIDE the `write_shorts_ost_audit` try/except (a lost audit file is a lost report; a title-less short is an irreversible publish). Safe to escalate because the check is one-sided: a missing/unreadable/too-short clip or a control band already saturated with the signature all PASS, so no measurement it cannot take ever fails a rendered day.
- **Shorts OST cascade — a GPS-bearing short burns only its own clip place, degrades loud** (`day_pipeline._render_day_shorts`): a GPS-BEARING short always burns the `short_ost_text_fn` vote over its own clip's GPS. An operator `--per-lf-location` override is never read on this path — it names the whole LF, not the clip. The closure coerces its positional `(t,lat,lon)` tuples to `{time,lat,lon}` dicts before the `dominant_location` vote (mirroring `build_resolved_location`) so the GPS quality filter reads the trace by key, on the same shape as the LF path. When a GPS-bearing short's own derivation degrades (quorum miss or exception) it inherits the parent-LF/drive-wide text with a `SHORT-OST-DEGRADED` WARN (rank, parent LF, reason, shipped text) and then **hard-fails** (`RuntimeError`, "Short place fallback FAILED") upstream of the encode — a WARN alone let a "To X" caption defect ship, so the fallback is no longer allowed to ship silently just because the parent LF's own label happened to be correct. This gate is scoped to the genuine degrade only: a short on a GPS-less day (nothing of its own to vote) keeps shipping its `"lf_label"` fallback unblocked — the operator override, else the county, else the drive-wide location, never the LF's destination POI (where the drive went, not where the clip was filmed). **A GPS gap never borrows a place**: on a day with GPS the shorts planner plans under the stop mask plus `stop_mask.build_gps_gap_mask`, which vetoes every second inside a fix-to-fix gap (or a lead before the first fix / a tail after the last) longer than `GPS_MAX_FIX_GAP_S` (= `route_claims.GAP_S`, 5 s: the same gap rule the Short route-claim gate applies, so a window the planner leaves open is never refused for a GPS gap; exactly 5.0 s is not a gap; fixes the claim gate rejects — non-finite, out of range, 0,0 — do not count), so every window the planner can pick holds the two fixes the place vote needs. The moving-budget target cap counts the same veto; the persisted `stop_mask_<date>.npz` stays the pure stop mask. **A short never spans a county line**: `day_pipeline._shorts_planning_mask` also ORs in `stop_mask.build_county_change_mask`, which reverse-geocodes the day's own usable fixes every `COUNTY_MASK_SAMPLE_S` (30 s, a sampling cadence — not a policy threshold) to `(county, state)`, skips a sample that geocodes to nothing (a miss is never a change), and for every pair of consecutive geocoded samples whose key differs vetoes `[t_prev - W, t_next + W]` (clipped to the day), where `W` is the planner's window length (`target_duration_sec`, default `DEFAULT_TARGET_DURATION_SEC`) — so no window can start inside it and cross the line. The geocoder is the shared cached one the shorts OST closure was built with (`_make_short_ost_text_fn` exposes it as `.geocoder`); with none (legacy / GPS-less day) the county veto is skipped. One INFO line per day logs the vetoed seconds. A short that still reaches the render with no fix of its own on a GPS day hard-fails (`Short place FAILED … no GPS fix of its own`) before any burn. The per-short region vote (`content_gates._make_short_regions_fn`) enforces the same `GEOCODE_QUORUM_MIN` floor as the OST closure, and a gate skip on a GPS-bearing short (empty/exception regions — the gate failing open) is counted with the OST degrades into one per-day `SHORTS-DEGRADE-SUMMARY` WARN. The fail-open path is decoupled from the quorum miss that also triggered the inheritance — when the inherited text is an `"A to B [via road]"` drive **arc** (`_is_arc_label`) AND the clip's own vote is empty, the gate HARD-BLOCKS (`RuntimeError`, `Short location invariant FAILED … inherited A-to-B drive arc`) upstream of the encode instead of shipping an arc nothing corroborates; a clean inherited county carries no arc and still fails open. GPS-less clips keep their silent legitimate skip. **Clip-DERIVED text is exempt from the town-form check** (`check_short_location_invariant(..., clip_derived=True)`): `short_ost_text_fn` renders the vote's settlement or destination POI (`dom.name or dom.county`) while `_make_short_regions_fn` renders the SAME vote's county, so reconciling one against the other is vacuous — it succeeded only where the town is EPONYMOUS with its county (e.g. Beaufort/Beaufort County, the cases the tests pin) and hard-failed every other settlement. Provenance comes from `_gate_short_ost_text`, which now returns `(text, source_index)`; the exemption holds only on source 0, and a clip vote the shorten/validate cascade rejects in favour of parent-LF or drive-wide text hard-fails the short (`Short place FAILED`) upstream of the encode, since that fallback was never checked against the clip. COUNTY-form text stays checked even when clip-derived — two renderings of one vote that disagree on the county is a real contradiction. Example: a label `'Exampleton, Tennessee'` against a `Sample County, Tennessee` vote would otherwise abort the run only after every LF burn had landed. **No operator exemption**: an `operator_override=True` pass let the operator's LF label burn verbatim on GPS-bearing shorts behind a `SHORT-OVERRIDE-UNCORROBORATED` WARN, so a short could publish the operator's label with its clip's own GPS never checked against it. **A voted settlement must lie on the clip's own trace**: the vote's settlement name is the zoom-18 reverse geocode's address claim, which can name a hamlet kilometres off the road — a short could burn a hamlet name whose fixes sat several km from it. Both drive callers (`phase_bc_day_first`, `shorts_extractor`) now pass `places_fn=_forward_geocode_places` to `_make_short_ost_text_fn`, which forward-geocodes `"<name>, <county>, <state>"` and keeps the name only when a settlement of exactly that name lies within `_TRACE_VERIFIED_PLACE_KM` (2 km) of an in-window clip fix — the same rule and helper (`content_gates._nearest_same_name_km`) the LF endpoint check uses. Otherwise, or on no timed fixes or a failing geocoder, the short burns the voted county with a `SHORT-PLACE-UNVERIFIED` WARN; a destination POI and a name-less vote are untouched. **Phase D re-checks provenance** (`phase_d_scheduling._build_social_posts_per_lf`): a GPS-bearing short whose sidecar `place_source` is not `clip_gps` — including a sidecar written before the field existed — raises before any plan or CSV is written, so a short rendered under the old rule is re-rendered, never published.
- **Shorts target is DERIVED from the publish plan**: `schedule_constants.required_shorts_per_lf(config, region=None, lf_day=None)` = `len(resolved shorts windows/day) × LF_PUBLISH_INTERVAL_DAYS` (7 — the same shared constant `scheduler.generate_drive_schedule` spaces LFs by, so slot supply and required count cannot drift). `run_day_pipeline` target: the per-LF count is Waypost's decision (`volume_source.shorts_per_lf()`; the hand-set `config.drive.shorts_per_lf_count` is retired), and `state["shorts_target"]` (operator `--shorts-target`, resume-authoritative `STATE_WINS`, per-LF semantics) can only lower it, × num_lfs. The old silent fallbacks to a hardcoded 9 (`shorts_target_count` day cap; `plan_shorts` `DEFAULT_TARGET_COUNT`) are unreachable when a drive config with `shorts_publish_times` exists; `shorts_target_count` survives only on the legacy single-video `longform_assembler` path. The day pipeline derives with `region=None` because the drive handler has already resolved the region/`--shorts-times` precedence into `config.drive.shorts_publish_times`. `required_shorts_per_lf(None)` raises (no publish plan to derive from); a `config=None` `run_day_pipeline` call (test/legacy, genuinely plan-less) keeps the planner default.
- **Shorts relaxation ladder** (`short_planner.plan_shorts`): `min_gap_sec` is a rung-1 preference, not a hard constraint. When the rung-1 greedy pick falls short of `target_count`, the ladder KEEPS the picks already chosen (immutable across rungs, best-score-first within each rung) and only ADDS fills at progressively relaxed constraints — rung 2: gap × 0.5; rung 3: gap 0 (adjacent, non-overlapping); rung 4: half the candidate stride + gap 0. Fully deterministic: explicit tie-breaks (score desc, then start-time asc), no dict-order dependence. Reaching target past rung 1 logs one INFO line (`SHORTS-PLAN: target N reached at rung R (rung1=a rung2=b …)`); rung-1 success stays silent. If rung 4 still can't reach target the timeline physically can't hold N non-overlapping windows: the planner returns the maximum found (never raises — the SHORTS-CONTRACT gate owns the contract failure and the `--allow-short-count` escape) and logs the ladder-exhausted breakdown.
- **Shorts duration bounds are configurable**: `short_planner.plan_shorts`'s `min_duration_sec`/`max_duration_sec`/`target_duration_sec` kwargs are threaded from `config.drive.shorts_{min,max,target}_duration_sec` (`day_pipeline.run_day_pipeline`, same `_shorts_kw` dict the target/gap fields use) — falling back to the `short_planner` module `DEFAULT_*` constants when `config.drive` doesn't carry the fields (legacy/test stubs). Operator overrides: `--shorts-min-duration` / `--shorts-max-duration` / `--shorts-target-duration` (`cli/handlers/drive.py`, applied directly onto `config.drive` then re-validated via `model_validate(model_dump())`, mirroring the `--shorts-times` cadence-dirty pattern — these are per-invocation config, not resume-persisted `PipelineState` fields). `DriveConfig.model_post_init` enforces `shorts_max_duration_sec <= video_types.SHORTS_MAX_DURATION` (60s, the YouTube Shorts hard ceiling) and `shorts_min_duration_sec <= shorts_target_duration_sec <= shorts_max_duration_sec`, raising `ValueError` on either violation.
- **Shorts-count contract gate** (`day_pipeline._enforce_shorts_contract`): `plan_shorts`' rung-1 greedy pick stops when min-gap excludes all candidates; with the relaxation ladder a planned shortfall now means physical impossibility, not tunable spacing. Two `RuntimeError` gates (greppable `SHORTS-CONTRACT`): planned < required right after `plan_shorts` — before any shorts encode/CSV/upload — and rendered < planned after the render loop (degenerate-skip / render-failure `continue`s must not erode a passing plan). Escape: `--allow-short-count` (argparse-sentinel, resume-persistent), which also drops the master-deletion gate back to actual-count matching. The planned target travels on `DayArtifacts.planned_shorts_count` so `phase_bc_day_first._expected_shorts_for_master_drop` count-matches produced-vs-REQUIRED — a shortfall day can never pass "count-matched" and delete its ~60 GB master.
- **Per-LF shorts capacity cap** (`day_pipeline.cap_shorts_to_per_lf_capacity`): the contract above is drive-wide and `plan_shorts` is day-wide (it picks the best-scoring windows across the whole day; attribution to LFs happens afterwards in `assign_shorts_to_lfs_by_source_window`), but slots are PER-LF — an LF's shorts window is `lf_date → next_lf_date` × the region's publish times, a hard ceiling of exactly `required_shorts_per_lf` (`scheduler`'s `while current_date <= next_lf_date`). So a day can plan the right TOTAL and still overfill one LF: for example, four LFs (4 × 14 = 56) could receive 11/21/10/14, leaving the second LF's surplus with no slot — the drive-wide count gate sees no shortfall, all 56 render, and `_assert_metricool_rows_have_schedule` then refused the whole CSV. Runs right after the planned contract, before any render: only OVER-full LFs are trimmed (an under-full LF keeps everything — levelling would discard placeable footage), the surplus is the LF's worst-`rank` shorts, and `_derived_per_lf` binds even when `--shorts-target`/`shorts_per_lf_count` asks for more, because the scheduler cannot place above its own ceiling. `DayArtifacts.planned_shorts_count` carries the POST-cap count so the master-deletion gate does not read a correctly-capped day as short. A failed mapping is a no-op (never delete content on a mapping error) — `_render_day_shorts` still re-raises an ambiguous multi-LF mapping. The same post-cap count (plus the per-LF target it was capped under, `DayArtifacts.shorts_target_in_force`) is persisted per-date on `per_day_completed`, so `phase_bc_day_first._enforce_reconstructed_shortfall` — the resume-path analog of the shorts-count contract gate — recognizes a legitimately-capped day (matching current target) instead of re-deriving the pre-cap `per_lf * num_lfs` total and raising a false shortfall; a raised `--shorts-target` since the day ran still falls through to the strict re-derivation.


The film CLI (`film.py main`) runs the delivery encode itself: the film is assembled to
`<output stem>.assembled.mp4` beside the output, `encode_final` writes the named `--output`, and the
scratch file is removed whether or not the encode succeeded — so a half-finished render never sits at
the path the caller was promised a finished film at, and the receipt's `outputs[].sha256` is the hash
of what was delivered. `--preflight-only` returns before either step. Writing `chapters.vtt` and
`publish.json` from the CLI is not wired yet: both need a route-time → film-time map of the assembled
timeline, which no module exposes today.
