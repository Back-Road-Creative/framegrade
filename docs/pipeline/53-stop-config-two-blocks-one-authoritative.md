## Stop config: two blocks, one authoritative

`config.yaml` carries two motion-stop knob blocks that are **meant to stay in lockstep**:

- **`stop_detection.{motion_threshold,min_stop_duration}`** is **authoritative** for the pipeline's actual stop removal. `StopProcessor.__init__` reads it, and `_analyze_motion_from_video` deep-copies the config and writes those values onto the copy's `dead_spots.{motion_threshold,min_duration_seconds}` before constructing the internal `MotionAnalyzer` — so the stop-removal cut is governed by `stop_detection.*` regardless of what `dead_spots.*` holds.
- **`dead_spots.{motion_threshold,min_duration_seconds}`** is consumed *directly* only by the standalone `analyze` command's `MotionAnalyzer` (the preview / CLI log line). If it drifts from `stop_detection.*`, the preview misrepresents what the pipeline will actually cut.

`config._warn_on_stop_knob_drift` logs a loud WARNING at `Config.load` when an operator file sets **both** blocks with diverging `motion_threshold` or min-duration. It fires only for loaded files (not bare `Config()` — the pydantic defaults legitimately differ: `dead_spots` 0.02/30 vs `stop_detection` 0.008/5.0), so programmatic construction stays quiet. `tests/test_stop_config_consistency.py` additionally hard-fails CI if the *shipped* sample `config.yaml` at the tree root ever drifts (both blocks ship at `motion_threshold: 0.008` and 5 s).

**`keep_segments` ↔ crossfade remap.** Downstream chapter/shorts timestamps invert stop removal via `shorts_time_mapping.map_from_edited_time`, which walks `keep_segments` assuming the edited timeline is the **hard-cut** concatenation (Σ of `seg_end − seg_start`). The pipeline's active stop-removal path is exactly that — stream-copy cut + concat-demuxer join (`_cut_and_stitch`, no re-encode) — so the remap is consistent. `StopProcessor`'s separate `crossfade_duration > 0` re-encode branch is **not** duration-preserving by inspection (`_render_crossfade` overlaps tails/heads); it is not on the pipeline's stream-copy path, and its edited-timeline duration semantics need a runtime check before it is ever wired into the day-master cut — tracked as a separate follow-up, not part of this change.
