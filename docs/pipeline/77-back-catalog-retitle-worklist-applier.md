## Back-catalog retitle worklist + applier

- `tools/retitle_worklist.py` builds the CSV. `suggested_title` prefers structured fields (`build_suggested_title`); with `--compose` (**default ON**) it falls back to the place text already embedded in the current (defective) title — never an invented place — via `_extract_place_from_title`: strip the `"{Region} Scenic Drive in 4K | {place}"` template pipe, a `"Highlights from {place}"` prefix, or a preposition-led prefix (`"To "` / `"#To"` / `"... Through To "`), then drop a trailing `"in 4K"`. A `duplicate-title` collision is disambiguated with the same `"(Part N of M)"` shape `title_builder.ensure_unique_titles` uses for sibling LFs. Every composed candidate is run through `retitle_apply.evaluate_row` (the SAME gate `retitle_apply` itself uses) before it's handed out — a candidate that would be `REFUSED` there stays `"needs-human"` instead of ever reaching the CSV. `--no-compose` reproduces the earlier plain (structured-fields-only) output byte-for-byte. `tools/retitle_apply.py --worklist PATH` gates each row's suggested title with the real checks (`content_gates.find_grammar_issues`, `place_corrections.find_denylisted`, 100-char cap, non-empty/non-placeholder) — any failure is `REFUSED` and never applied. Dry-run by default; `--apply --yes-live` fetches the live snippet, `SKIPPED_STALE`s a row whose live title no longer matches the worklist's `current_title`, else mutates only `snippet.title` (categoryId/tags untouched) via `videos().update`, plus `snippet.description` in the same call when the row carries a `suggested_description`. A description row must also carry `current_description`, the drift check: a live description that no longer matches it is `SKIPPED_STALE`. The suggestion passes the same grammar and denylist gates, plus YouTube's 5000-byte and no-`<`/`>` limits (else `REFUSED`). `retitle_worklist.rewrite_description_place(description, old_place, new_place)` builds that suggestion for a wrong-place Short: a whole-word swap in the text, and every place hashtag (old place, its state, a smashed route tag) replaced by the new place's `_location_hashtags`. It returns `None` (leave the description) when the text never names the old place, or when a place tag can't be isolated. Sequential, one retry, stops on the first API error; every outcome is appended to `<worklist>.audit.jsonl` (`old_description`/`new_description` included on a description row).
