## Edit timeline and assembly receipt (implementation)

- **Receipt schema** (`gomoveshift/pipeline/edit_timeline.py`): `keycut-assembly-receipt/1` is what the cutting library writes after an assembly: the requested ranges, one span per cut actually made (source range, output range, `copy` or `reencode`, why), and the output file. `load_receipt(path_or_dict)` returns frozen dataclasses (`AssemblyReceipt`, `ReceiptSpan`); `to_dict()` round-trips the input exactly.
- **Validation.** Every violation raises `ReceiptError` (a `ValueError`) whose message starts with the failing field, e.g. `spans[1].output_start: not contiguous with spans[0].output_end`. Checked: schema id; `provenance`, `method`, `reason`, `duration_source` enums; `time_base == "seconds"`; types and finite numbers; half-open intervals (`start <= end`) for requested pairs and each span's merged, source and output ranges; `source_end == merged_end`; `source_start == merged_start` for `reencode` and `>= merged_start` for `copy` (a copy span snaps forward to a keyframe, never back); `requested_indices` non-empty and inside `requested`; `spans[i].index == i`; output spans start at 0 and are contiguous within 1e-3 s.
- **Order.** Spans are in output order, which may differ from source order: the cutting library honours the requested order.
- **Fixture.** `tests/fixtures/assembly_receipt_v1.json` is a frozen 3-span receipt (a copy span snapped forward of its merged start, a re-encode span, and a span merged from two requested ranges). Tests: `tests/test_edit_timeline_receipt.py`.
- **`EditTimeline`** (same module): output-time to source-time mapping from what was actually assembled. Build with `EditTimeline.from_receipt(receipt, crossfades=(), inserts=())`, or `EditTimeline.from_segments(segments, crossfade=0.0)` for a planned timeline from kept `(start, end)` segments.
  - `output_to_source(t) -> tuple[SourcePosition, ...]`: empty inside an insert hold or outside `[0, duration)`; two positions (outgoing first; weights ramp 1-x and x and sum to 1) inside a crossfade; otherwise one. `SourcePosition` is `(time, weight, span_index)`.
  - `source_to_output(t) -> float | None`: `None` when that source second was cut (including a copy span's head before its keyframe-snapped start). A cut is never interpolated across. A source second used twice answers with its first use in output order. The two mappers stay inverse outside a crossfade overlap; inside one, a source second keeps the output clock of its own span.
  - `source_to_output_snapped(t)`: the chapter-placement variant. A second in a cut snaps to the end of the footage before it (0 before the first span, the total after the last), and span ends are inclusive.
  - **Crossfade** `Crossfade(after_span, duration)`: the next span starts `duration` before the previous one ends, so the timeline is the sum of the spans minus the overlaps. Same semantics as `map_from_edited_time(..., crossfade)`. `duration` must be positive and no longer than either neighbour; one span cannot overlap both neighbours by more than its length.
  - **Insert** `Insert(at, duration)`: an output-time hold with no source. `at` is on the timeline before inserts; everything at or after it moves later by `duration`; inside a span it splits that span. An insert inside a crossfade overlap is rejected.
  - Receipt spans with differing output and source length (a probed duration) map proportionally inside the span; equal lengths map as a plain offset.
- **Mappers now delegating to `EditTimeline`** (public signatures unchanged; their existing tests are untouched):
  - `gomoveshift/analysis/shorts_time_mapping.map_from_edited_time` (and `VideoToGpsTimeMapper`) use `output_to_source`; inside a crossfade overlap it still answers with the incoming segment, as before.
  - `MarkerMerger.map_to_edited_time` (chapter placement) uses `source_to_output_snapped`. It gained an optional `crossfade=0.0`. `ChapterGenerator._map_to_edited_time` calls it without one: the generator holds no crossfade information, so it passes 0 (hard cuts).
  - `VideoAssembler._adjust_chapters_for_trims` uses `source_to_output`; a chapter on a trimmed second is dropped, as before.
- **Not wired yet.** Nothing persists or reads a receipt in the day pipeline; the mappers still build a planned timeline from `keep_segments`. Tests: `tests/test_edit_timeline_mapping.py`.
- **Planned-timeline edge case.** A segment shorter than twice the crossfade clamps its seam to half its length (the old arithmetic produced a negative advance there); zero-length segments contribute nothing.
