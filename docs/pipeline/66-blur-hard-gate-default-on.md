### Blur hard gate + default-on — `pipeline/blur_gate.py`

The gate guards every blur-enabled run (`config.drive.blur_enabled`; default on). Because the encode composites the blur iff a mask is present, "mask present at encode time" ≡ "FINAL is blurred", so the gate guards that equivalence:

- **Resume repopulation.** `BlurDetectionStage` is skipped once complete, so a resumed `ctx.blur_mask_path` comes back `None`; `resolve_mask` reloads it from the known `_stages/<project>_blur_mask.mkv` path before the encode, and `check_mask_ready` hard-fails (upstream of the irreversible encode) if blur is required but no usable mask exists.
- **Durable applied-marker.** A successful blurred encode stamps `<project>_FINAL.mp4.blurred`; the resume-complete branch (which accepts an existing FINAL without re-encoding) refuses any blur-required FINAL lacking the marker — closing the "FINAL encoded before blur was on" silent drop. Both checks no-op when `--skip-blur` (or `blur_enabled` off). Thumbnails/shorts derive from the blurred master for free (they run after the encode sets `ctx.current_video`).
- **Pixel corroboration.** The marker is an *attestation*: it records that an encode once claimed to composite the mask, and a stale, copied or hand-created one attests just as loudly, so on its own it never said anything about the artefact being accepted. `check_applied` now also runs `masked_regions_look_blurred`, which decodes `_SPOT_CHECK_SAMPLES` frames from the FINAL and the frame-aligned mask at 480px wide and compares high-frequency energy (mean absolute Laplacian) inside the mask against the same frame outside it. One frame under `_BLUR_DETAIL_RATIO` is proof the composite ran and short-circuits; the gate fails only when every measurable frame shows the masked region as sharp as its surroundings. The threshold is loose on purpose — the composite's blur radius collapses detail by an order of magnitude while an unblurred region sits near 1.0, and that gap is what makes a one-sided test safe. Deliberately one-sided in the other direction too: no mask, an unreadable file, a geometry mismatch, or a mask covering under `_MIN_MASK_COVERAGE` of the frame all return *pass*. Absence of measurement is not evidence of an unblurred ship, and a privacy gate that hard-fails a six-hour encode over a measurement it could not take would be worse than the hole it closes — the marker remains the necessary condition, the pixels only ever add corroboration.
