# Private night projects

Photos → Night projects redevelops **existing `.linear` stacks** into a private
16-bit TIFF and matching JPEG without RAW decoding, registration, publishing or a
journey stub. Natural is a conservative baseline; Accent/Bold are explicit tonal
variants, not the image-specific experimental local-contrast recipes. Complete
means all requested files passed integrity checks, **not** that image quality was
approved. Review foreground edges, stars and color before selecting an export.

Configure `GMS_NIGHT_SOURCE_ROOTS` as an `os.pathsep`-separated list of allowed
source directories for the console. Unconfigured roots disable creation. Projects
live in `GMS_CONSOLE_DATA_DIR/night-projects`; authenticated preview routes check
brand ownership and never expose arbitrary local paths. Sources remain read-only.
The console's **Inspect collection** form accepts one directory inside those roots
and uses the same bounded header scan as CLI `--scan`. It shows likely lights and
darks, compatible sequences and capture span, unreadable/refused entries, and
validated or invalid `.linear` folders. After inspection, the operator can select
best stills, a deep still, a shared-tone timelapse, or star trails and the exact
sequence to use. Submission rescans current headers, persists one immutable typed
request, and launches its durable worker. Scanning itself never launches a worker.
The detail screen separates referenced RAW, saved-linear, and generated byte totals;
shows per-product state, attempts, exclusions and evidence; and serves only receipt-
validated JPEG previews and MP4 video through private no-store routes. TIFF masters
and local paths are never browser download URLs. Receipt-bearing attempts are
protected from read-only cleanup suggestions. The storage section presents a
review-only retention proposal for unreferenced, receipt-free attempts after a
project reaches a terminal state. It names the potential bytes and the protected
dependency count but has no deletion action or deletion authorization. Sources,
current outputs, recoverable receipts and private keepers stay protected. This
screen is a private project view, not public gallery registration. The normal
privacy/GPS-stripping publishing path remains separate.

A completed still product can be selected with **Prepare private keeper**. This
creates a new copy under the project workspace, never changes its master, and uses
the same people, face, plate and vehicle-occupant detectors as gallery ingest. All
four detector classes must be configured and verified; an inconclusive class or a
detection failure refuses the export. The copy is rebuilt from pixels as an ICC-
tagged JPEG, so source EXIF and GPS are absent, and a receipt binds its source hash,
project build/runtime, privacy-class evidence, obscured-region count, output hash
and size. Repeating the action reuses the validated receipt. A changed or corrupt
copy is unavailable rather than silently regenerated over the evidence. Selected
keepers remain private, require visual quality review, and are explicitly marked
unpublished; this action does not schedule or post them.

A completed timelapse offers a separate **Prepare privacy-checked private video**
action. It queues a durable job under the shared media admission gate, so its
status, retry evidence and heartbeat survive the browser session. The job validates
the product receipt and source hash, then uses the established video detector/tracker
and mask compositor for people, faces, plates and vehicle occupants. All four model
classes must be verified before rendering, and a cabin-coverage gate refuses the
render if the mask misses a corroborated vehicle occupant. The new MP4 is encoded from the real
timelapse with its audio retained, location metadata removed, and a receipt binding
source/output hashes, build/runtime, detector-class evidence, decoded frames and
masked frames. Repeating the action reuses that validated receipt; a changed copy is
refused. The result remains private, unpublished and subject to visual quality and
privacy review.

For best stills, the project screen finds other Natural, Accent and Bold requests
whose saved linear input identities match exactly and lays their receipt-validated
previews out together. Missing treatments can be queued from that screen as
best-still-only projects; current RAW/video work is not repeated. A pending or
failed comparison stays visible with a link to its own status rather than offering
a duplicate launch. The three presets use recorded global luminance curves on the
same captured pixels. The comparison explicitly remains a visual review of stars,
tree edges, color and noise, not an automatic quality score or recovered new detail.

The same queue is available from the CLI:

```bash
cd /path/to/installed/service
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --scan /media/night
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --source-root /media/night --collection /media/night --products best_stills timelapse --sequence-index 0 --recipe natural
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --source-root /media/night --sources /media/night/example.linear --recipe natural
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --project PROJECT_ID --status
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --project PROJECT_ID --pause
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --project PROJECT_ID --cancel
python -m gomoveshift photos night --workspace /durable/private/night-projects --brand gomoveshift --project PROJECT_ID --resume
```

`--scan` is a read-only inventory. It reads regular RAW files and EXIF headers,
reports capture span, stable exposure/ISO/frame-geometry sequences across midnight, unreadable
metadata, existing valid/invalid `.linear` manifests, and paths it refused. A file
is only called a likely dark when its filename or an ancestor directory explicitly
says dark/calibration; the scan never guesses from pixels. Symlinks are refused,
the walk is bounded to 20,000 entries, and no project or output is created.
Recorded pixel dimensions split otherwise compatible runs when camera geometry
changes. Missing dimension tags remain grouped only with other unknown-geometry
frames and are labeled unknown; the scanner never substitutes an embedded
decode size or decodes the RAW payload to guess.
Valid lights that form a run shorter than the sequence minimum remain visible as
unsequenced, with their paths and the exposure, ISO, geometry, clock or gap boundaries
before and after the run. Their absence from a selected timelapse is never silent.
Each sequence says whether every frame carried a recorded UTC offset, only some
did, or timing is camera-clock-only. A split caused by a capture gap, clock reset,
ISO change or exposure change is recorded and shown instead of silently grouping
the frames into one requested video.

Night output requests have distinct typed contracts for best stills, timelapse,
star trails, and a deep still. A still receipt cannot satisfy a timelapse request;
video requires an MP4 result and the other products require a supported still
image plus a JSON receipt. Every still product also derives an ICC-tagged JPEG
preview from its validated 16-bit master; the preview is a display conversion of
real master pixels, not a generative or content-aware edit. The project store can persist a schema-2 typed request
before processing begins. Its immutable identity includes ordered requested
products, selected sequence, current build/interpreter and local source identities.
RAW identity records path, size, nanosecond modification time, device and inode;
linear inputs record a manifest hash. This detects ordinary card replacement and
source changes without decoding pixels, but is not a cryptographic hash of every
RAW payload. Request metadata is capped at 1 MiB and 4,096 RAW inputs.
The immutable runtime identity also records Python and relevant package versions,
plus resolved Python/ffmpeg/ffprobe paths and binary hashes. A changed source
build, interpreter, dependency set or media binary requires a new request rather
than silently resuming under different processing code.

Creation rejects missing prerequisites before a worker starts: best stills need
one validated linear stack, a deep still needs at least two, and timelapse/trails
need a selected compatible sequence with at least two frames. Symlinks, special
files and inputs outside configured roots are refused. Repeating the same request
returns the same ID. The supported project processor executes schema-2 tasks from
either the console or CLI. `--collection` requires at least one `--products` value
and a source root; request-only options are refused with legacy `--sources` and
read-only `--scan`.

## Product render receipts

The product adapter calls the existing engines: conventional saved-linear
development for best stills, the shared-tone streaming timelapse, streaming
maximum trails, and the validated linear-artifact deep combine. It publishes an
aggregate `product-receipt.json` only after every listed output passes its media
type, size and SHA-256 checks. The receipt binds project, product, recipe, build,
runtime and the complete saved input identity. A timelapse requires a probeable
MP4 video stream and records actual duration, dimensions and codec; a TIFF cannot
satisfy it. Still products require TIFF primaries. Trail and deep-still adapters
derive receipt-bound JPEG previews after the master is complete. JPEG, NPY and JSON companions
are validated according to their formats.

Receipts record requested and contributing frame counts, capture bounds and any
dropped frame path, timestamp and reason. An output with dropped frames is
`partial`, not silently complete. Best-still item failures preserve valid sibling
renders and remain visible in the aggregate result.

Acceptance includes a real production-encoded MP4 from deterministic captured-pixel
frames. The typed product validator probes that file, records its duration,
dimensions and codec, and revalidates the receipt; a mock byte string is not the
video acceptance boundary.

The schema-2 worker runs requested products one at a time under the same shared
media admission and project lock as saved-linear development. It reserves a
conservative output allowance before each task, distinguishes memory/disk waits
from invalid inputs, and stops an immutable project-budget overrun without
deleting the valid bytes. Pause takes effect between product stages. Each task
records attempts, current stage, last progress, its receipt and evidence. A
receipt published before a database commit is adopted on restart; a tampered or
mismatched output is retained but never reused. Failures in one product do not
prevent independent siblings from running, and overall exit 0 requires every
requested product to be complete.

A project ID binds brand, input manifest identities, recipe and processing build.
Double submission reuses that request. Repeated console Resume requests also reuse
a matching live worker, including one polling for resources; a stale waiting
record without a live process permits a fresh worker. Concurrent clicks in the
same console are serialized before launch. The worker checks source identities, admits
memory before loading reusable artifacts, and records each item's attempt and
failure. Matching receipts reuse good results. A crash after receipt publication
but before DB commit is recoverable by adopting that attempt; an existing TIFF
alone never establishes success. A missing/corrupt output is rendered into a new
attempt, preserving the earlier files. A changed build/input requires a new
request, never an undocumented continuation of old settings.

Workers share a local OS-user admission lock even across project workspaces.
Set `GMS_NIGHT_ADMISSION_LOCK` to the **same host-mounted lock file** across
containers/accounts to share admission there. Never remove a live lock file.
Locks release automatically when a process ends. This serializes participating
night workers and the supported `photos astro`, `astro-combine` and `astro-inspect`
CLI commands. Astro includes trails, timelapse, triage and from-master contact
sheets. A busy command exits 2 before decoding or writing media, so rerun it after
the current worker finishes; legacy CLI commands do not become durable projects
automatically. Help and standalone lightweight metadata/header helpers need no
heavy admission. Direct Python callers, drive jobs and CI remain outside this
fence. Admission follows the CLI handler lifetime; abrupt parent death does not
retain capacity for orphaned encoder/converter descendants. Memory availability
includes a conservative reserve; it is not a hard OS reservation. Only lock
metadata uses the system temporary directory; images and SQLite remain durable.

Resource waiting is bounded by `--wait-seconds` (600 default), checked every
`--poll-seconds` (15 default). Exit 0 means complete, 1 failed/partial/blocked,
2 waiting/paused; inspect the durable project status. Pause and cancel are cooperative
between stages and do not kill an active render. Cancel exits 1 after preserving
completed artifacts and disables automatic retry; only explicit Resume continues it.
Resume clears both control flags and keeps completed items. Process
identity uses PID, boot ID and start fingerprint; a vanished worker is interrupted,
never inferred successful. Browser closure does not own worker lifetime.
Liveness reconciliation updates only the exact observed database snapshot, so a
concurrent completion, resume, pause or cancel cannot be overwritten by a stale reader.
Receipt adoption rechecks the project build after validation, just as a new render
does; a build change cannot complete an old request through the recovery path.

## Storage admission

The backend accepts an optional positive integer `storage_budget_bytes` when
creating a request. Set it in the console's optional Project output budget (GiB)
field or use `--storage-budget-gib 1.5` with CLI `--sources`. Blank/omitted means
explicitly uncapped; no environment default or hidden limit is applied. GiB inputs
must be finite and positive, within 1 byte through 2^63-1 bytes, and are rounded
down to whole bytes. The detail view shows the saved limit in exact bytes and GiB.
Passing a budget with CLI `--project` is refused before any work starts. A configured budget is part of immutable project
identity, so increasing it creates a new request and preserves the previous one.
All generated files, including incomplete attempts, consume the project budget.
Source trees are excluded, symlinks and uncountable entries fail closed, and no
files are deleted to make room.

Before a new render, admission estimates 12 bytes per source pixel plus 16 MiB
for TIFF, JPEG and metadata; preview-only recovery reserves 6 bytes per pixel
plus 4 MiB. Output free space must also retain 1 GiB of headroom. These deliberately
conservative estimates are not filesystem quotas or reservations against outside
writers. Actual usage is checked again after writes; an unexpected overrun is
preserved and waits for review rather than continuing or deleting partials.
Shortage records `waiting` with byte counts and exits 2; malformed dimensions fail
the item. Existing usage is checked before decoding. A valid completed receipt can
be reused at the budget limit with no extra free-space requirement because reuse
writes no media. SQLite still needs working space for status records.
Completed receipts are checked before any preview recovery, so an unrelated
pending attempt cannot block reuse by demanding additional output capacity.

## Current boundaries

- Collection discovery and typed product submission are available through the
  screen. Requests reuse validated linears and compatible sequences; they do not
  invent calibration frames, auto-rank artistic quality, or create a new RAW stack.
- Horizon-only stack reconstruction can retain tree ghosts. Output receipts mark
  quality review required. Experimental reference/stack masking is not promoted.
- A failed preview with a verified pending receipt is rebuilt from the TIFF without
  recomputing the master. An unverified partial remains preserved, not trusted.
- Schema-1 projects now pin source, interpreter, dependency versions and media
  binary hashes, but an installed directory is still not an immutable container.
  Use the reserved installed build and create a new request after upgrades.
- Production console reprovision recreates the container and can interrupt its
  child worker. Attempt directories and receipts remain durable, startup records
  the lost child as interrupted, and build/runtime identity blocks automatic
  adoption under the new image. Release only when no night worker is active;
  after an interrupted upgrade, inspect the preserved result and create a new
  request rather than forcing the old identity to continue.
- Private projects and privacy-checked still keepers are discoverable through the
  Media library/project view. Gallery registration, scheduling and host-wide resource
  reservations remain separate. No source or intermediate is deleted.
- Console retry supervision requires the existing ticker. CLI-only requests are not
  silently enrolled. A live-worker stall is made visible for review; it is not killed,
  replaced, or force-cleared automatically.

See [natural recipes](astro-natural-recipe.md) and [render receipt contract](night-render.md).

The automated CLI smoke check invokes the actual module entry point on a tiny
synthetic linear capture, validates profiled TIFF/JPEG output and durable project
state, then resumes the same request and checks that verified files are not
rewritten. It uses real resource admission and reports an explicit skip if the
host lacks the required memory or disk reserve; it never uses private source media.
The typed-product smoke also creates Best Stills and Deep Still through the real
CLI from two synthetic star-field linears, validates both product receipts, and
proves that resume preserves every output and source byte.

Night workers and supported heavy astro CLI commands use the same shared admission
helper. Non-regular lock files are refused before image work; lock files are never
unlinked during normal completion or recovery.

## Durable console retry supervision

New console submissions and explicit Resume record retry intent outside immutable
image identity. With `GMS_CONSOLE_TICKER=1`, the existing console ticker revisits
at most 20 due projects and launches at most one worker per pass, oldest due first.
CLI-only/historical requests are never silently enrolled. The project screen shows
the in-process ticker's actual health, retry intent, next eligible check, and
observations. Configured, starting, healthy, stopped, overdue, and failed supervision
passes are distinct states.

Typed memory/admission/free-space waits use persisted exponential backoff from
60 seconds to one hour. Immutable-budget waits, failed/partial renders, changed
builds, and unclassified legacy waits require review; they are never blindly
relaunched. A proven dead running/interrupted worker gets at most three automatic
restarts. Pause prevents launches; explicit Resume reenables intent. The bounded
CLI polling worker remains authoritative while alive, including after console
restart.

While a typed product engine is running, its worker records a heartbeat immediately
and every 30 seconds. More than 90 seconds without a heartbeat is visible as missing
liveness evidence. Best-still inputs and deep-stack completion report milestones;
timelapse and trail engines report each inspected frame, including a rejected frame.
Milestone writes are throttled to the first, last, and at most one intermediate write
per 15 seconds. A current heartbeat with no milestone for two hours on best stills,
four hours on a deep still, or twelve hours on timelapse/trails is shown as a stage
stall. These thresholds request review only; they never permit a duplicate launch,
termination, or replacement of a process whose identity remains live.
When at least one milestone exists, the project screen derives an approximate
remaining time for the current stage from persisted elapsed time and completed
inputs. It updates as milestones arrive and explicitly excludes queueing and later
stages; waiting projects never receive a fabricated ETA.

HTTP and ticker launches share a cross-process lock and durable pre-launch claim.
A claim never expires into permission to overlap. An acknowledged Jobs record with
PID/start evidence can reconcile a launcher crash. An ambiguous crash around Popen
or missing worker identity remains held for manual process reconciliation, even
on Resume; the supervisor does not provide an unsafe force-clear button. Existing
heavy-worker admission remains a second fence. No logs or image pixels are read
by supervision, and each project's metadata is limited to 1 MiB. Malformed rows
are isolated and displayed as unavailable/manual-review observations.
Metadata reads close their SQLite connection on success and failure without relying on garbage collection.

Supervision failures are isolated from social drains and other observers. The
Ticker records separate `last_night_ok_at`/`last_night_error` health; this is not
proof that a paused/disabled project is being retried. A stopped console cannot
supervise: deployment/service availability remains an operator responsibility.
